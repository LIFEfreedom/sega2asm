# Карта кода

57 260 инструкций m68k в 354 сегментах. Ниже — что где лежит.

## Как построена

Классификация механическая, а не «на глаз»: для каждой инструкции
считается, упоминает ли она известную базу данных (массив юнитов, карты,
состояния игроков, буферы графики, меню), обращается ли к VDP и является ли
вызовом BIOS. Признаки суммируются по банкам. Скрипт воспроизводим, так что
цифры можно пересчитать после любого изменения `game.yaml`.

## Три слоя

| банк | инстр. | юниты | карта | игроки | состояние | графбуфер | меню | перепись | парам. | VDP | трапы |
|---|---|---|---|---|---|---|---|---|---|---|---|
| `$00` | 10237 | 23 | 4 | 35 | 126 | 3 | 24 | 0 | 0 | **296** | **273** |
| `$01` | 11516 | **82** | **76** | 57 | 23 | 0 | 5 | **28** | **47** | 46 | 5 |
| `$02` | 10412 | 48 | **88** | **86** | 14 | 0 | 0 | **44** | 0 | 14 | 35 |
| `$03` | 6708 | 4 | 0 | 3 | 78 | 0 | 27 | 0 | 0 | **282** | **188** |
| `$04` | 6767 | 5 | 0 | 0 | 44 | 2 | 4 | 0 | 0 | **334** | **194** |
| `$05` | 11620 | 9 | 4 | 3 | **162** | **132** | **104** | 0 | 1 | **325** | **423** |

Разделение выходит чёткое:

**`$00` — ядро и BIOS.** Здесь сам обработчик line-F и все его функции,
инициализация, обработчики прерываний. Отсюда же идут 273 вызова BIOS и
296 обращений к VDP. Подсистема описана в [game-engine.md](game-engine.md).

**`$01`–`$02` — игровая логика.** Почти не трогает VDP (46 и 14 обращений
на двадцать две тысячи инструкций). Банк `$01` — юниты, карта, параметры
видов, поведение, бой. Банк `$02` — команды игрока, цены, операции с
картой, перепись. Это самая разобранная часть.

**`$03`–`$05` — вывод.** 941 обращение к VDP и 805 вызовов BIOS против 51
и 40 у логики. Банк `$05` — самый большой и построен вокруг буфера
`GfxWorkBuffer`.

## Что лежит в каждом банке

### `$00` — ядро

| адрес | что |
|---|---|
| `$000668` | обработчик line-F, вход в BIOS |
| `$000690` | таблица BIOS, 57 записей |
| `$000AB6`–`$001F00` | сами функции BIOS, см. [game-engine.md](game-engine.md) |
| `$000D5A` | таблица методов распаковки |
| `$00F8A8` | таблица «символ → тайл», копируется в `$FF0070` |
| `$0142A4` | построение списка видимых юнитов |
| `$0150FA` | индекс ассетов |
| `$0151B2` | выгрузка таблицы спрайтов, самая вызываемая процедура игры |

### `$01` — юниты, поведение, бой

| адрес | что |
|---|---|
| `$016976` | главный цикл обновления, 255 слотов |
| `$016AB4` | пересмотр поведения, двухуровневый диспетчер |
| `$016AF4`, `$016BF2` | таблицы переходов по действию и по виду |
| `$016C2E`–`$0176C0` | шестнадцать скриптов поведения |
| `$017700`–`$01A900` | правила поведения |
| `$01B1AE` | развязка стычки |
| `$01B4F8` | расчёт урона |
| `$01CA84` | создание юнита |
| `$01D1FE`–`$01D36C` | модуль здоровья |
| `$01D746` | свёртка переписи |
| `$01FAEE` | шаблоны типов, 91 запись |
| `$01FC5A` | дескрипторы видов |

### `$02` — команды и карта

| адрес | что |
|---|---|
| `$020768` | покраска клетки местности |
| `$0211BC`, `$021B2A`, `$021B42` | доступ к местности |
| `$022340` | цены команд, двоично-десятичные |
| `$02248C`+ | блоки параметров видов |
| `$0236F8`, `$0238CA` | обработчики команд «растения» и «яйца» |
| `$0237DE`, `$023864` | команда улучшения и превращения |
| `$024A2A`+ | проверка и списание денег |
| `$02FC84`, `$02FD36` | обход всех видов |

### `$03`–`$04` — экраны и меню

Крупнейшие процедуры: `$048276` (2508 инструкций), `$0355FA` (1772),
`$04DD18` (1370), `$03EEBE` (1196), `$03121C` (1144). Все начинаются с
настройки регистров VDP и очистки планов, то есть это построение отдельных
экранов. `$04DD18` дополнительно копирует таблицу «символ → тайл» из ROM.

### `$05` — вывод и палитры

Построен вокруг `GfxWorkBuffer` = `$FFE45C`: туда распаковываются данные
трапом `$FF10`, после чего идёт побайтовая обработка. Характерный приём —
работа с полубайтами и сдвиги на единицу с ограничением в 7:

```asm
	move.b	(a2),d5
	lsr.b	#1,d5
	cmpi.b	#$07,d5
	bge.s	loc_0519EE
	addq.w	#1,d5
	andi.b	#$07,d5
	lsl.b	#1,d5
	move.b	d5,(a2)+
```

Формат CRAM на Mega Drive — три трёхбитных компонента в слове, и такой
код меняет их яркость. То есть это **затемнение и высветление палитр**.
В другом месте (`$052A4E`) полубайты ограничиваются сверху: `$F`→`$C`,
`$D`→`$B`.

Сорок один вход в банк вызывается из банков `$00`, `$02`, `$03` и `$04`.

## Чего в карте нет

- Имён у процедур банка `$05`: их сорок один вход, и каждый требует
  отдельного разбора. Роль банка установлена, отдельные процедуры — нет.
- Разбора крупных экранных процедур банков `$03` и `$04`.
- Что делает диспетчер по таблице `data_12` для методов распаковки 2, 3,
  6 и 7 — в данных они не встречаются.
