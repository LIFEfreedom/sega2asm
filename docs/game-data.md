# Игровые данные: команды и цены

Найдено разбором кода. Здесь только то, что подтверждается ROM; там, где
вывод неполный, это сказано прямо.

## Меню команд — `$0496F0`

Строки с терминатором `$00`, кодировка JIS X 0201 (см. `game_charmap.tbl`).
Верхний уровень меню:

| адрес | текст | значение |
|---|---|---|
| `$0496FE` | `ｼｾﾞﾝ` | 自然 — природа |
| `$049708` | `ﾀﾏｺﾞ` | タマゴ — яйцо |
| `$049711` | `ｼｮｸﾌﾞﾂ` | 植物 — растения |
| `$04971A` | `ｼﾚｲ` | 指令 — приказы |
| `$049723` | `ｷｬｯﾁ` | キャッチ |
| `$04972E` | `ｶｲｿﾞｳ` | 改造 — переделка |
| `$049736` | `ﾕｳﾄﾞｳ` | 誘導 — наведение |
| `$049741` | `ﾏｰｷﾝｸﾞ` | マーキング — маркировка |

## Природные команды — `$04975E`

Формат: сначала 7 слов-смещений (14, 22, 30, 38, 46, 54, 62), затем сами
строки по 8 байт. Смещения считаются от начала таблицы смещений.

| индекс | адрес строки | текст | значение |
|---|---|---|---|
| 0 | `$04976C` | `ｱﾒ` | 雨 — дождь |
| 1 | `$049774` | `ﾋﾃﾞﾘ` | 日照り — засуха |
| 2 | `$04977C` | `ｶﾐﾅﾘ` | 雷 — молния |
| **3** | `$049784` | `ｵｵｱﾒ` | 大雨 — **ливень (HeavyRain)** |
| 4 | `$04978C` | `ﾎﾞｳﾌｳ` | 暴風 — буря |
| 5 | `$049794` | `ｼﾞｼﾝ` | 地震 — землетрясение |
| 6 | `$04979C` | `ｲﾝｾｷ` | 隕石 — метеорит |

Ниже, с `$0497B0`, тем же способом лежат названия динозавров:
`ｽﾃｺﾞ` (стего), `ﾄﾘｹﾗ` (трицера), `ｱﾛ` (алло), `ﾃｨﾗﾉ` (тиранно).

## Таблицы цен — внутри `data_173` (`$022340-$0235F6`)

Четыре параллельные записи с шагом около `$28C` (652 байта), в каждой —
список из 10 значений:

| адрес | значения |
|---|---|
| `$022550` | 100, 125, 150, 1200, 500, 1650, 1450, 1750, 1550, 450 |
| `$0227DC` | 700, 800, 1000, **1800**, 400, 2500, 2300, 2800, 2500, 1000 |
| `$022A68` | 400, 500, 900, **1500**, 350, 2400, 2100, 2500, 2200, 500 |
| `$022CF4` | 120, 140, 160, 240, 1300, 1800, 1300, 2400, 1300, 800 |

## Что это даёт по спорным ценам

Разбор японского мануала оставил три нерешённых расхождения: HeavyRain
1800 против 1500, куст 700 против 800, смена вида у Fat 300 против 400.

**Похоже, спорить было не о чем: цена зависит от записи.** Значения 1800 и
1500 стоят на ОДНОЙ И ТОЙ ЖЕ позиции в двух разных записях (`$0227DC` и
`$022A68`), а 700 и 800 — соседние значения внутри одной записи. То есть
мануал и код описывали разные контексты, а не противоречили друг другу.

### Чего я НЕ доказал

Соответствие «индекс в таблице цен → конкретная команда» не установлено.
Против него говорит арифметика: природных команд семь, а в записи десять
значений. Возможные чтения — 7 погодных плюс 3 других, либо совсем другая
группировка. Чтобы закрыть вопрос, нужно найти код, который индексирует эти
таблицы; прямых ссылок на них нет, доступ идёт через базу `data_173` со
смещением, и цепочку я не дотянул.

Так же не установлено, чем различаются четыре записи. Величины растут от
записи к записи, что похоже на уровни сложности или стадии игры, но это
догадка, а не вывод.


## Структура состояния игры

`GameState` = `$FF0564`. Раньше я назвал этот адрес `WorkBuffer` по первому
впечатлению — туда пишет распаковщик. **Это была ошибка:** обращений вида
`$NNNN(a5)` к нему 1012 штук со смещениями до `$3Fxx`, то есть структура
занимает 16+ КБ, а распаковка лишь использует её голову как временную
область. По соглашению кода регистр `a5` почти везде держит эту базу.

### Записи видов — `GameState + $86` = `$FF05EA`

Шесть записей по 90 байт (`$5A`), ровно по числу видов из таблицы имён.

Доказательства:

| адрес | код | что показывает |
|---|---|---|
| `$0565DA` | `move.w $C(a5),d0` / `mulu.w #$005A,d0` | индекс × размер записи |
| `$0565E2` | `tst.b ($49,a1,d0.w)` | поле `+$49` — байт состояния |
| `$0565E8` | `tst.b ($4D,a1,d0.w)` | поле `+$4D` — байт состояния |
| `$02FC84` | цикл `dbf` на 6, шаг `adda.w #$005A` | проверка `+$4D == 2` у ВСЕХ шести |

Цикл на `$02FC84` читается так: если поле `+$4D` равно 2 у всех шести видов,
ставится флаг `+$25` у другой структуры и из ROM `$031D16` копируется
таблица в 6 байт. Похоже на условие завершения по всем видам сразу.

### Чего я НЕ установил

Что именно означают поля `+$49` и `+$4D`, из этих мест не видно — видно
только, что это байтовые состояния и что 2 у `+$4D` является особым
значением. Полная раскладка 90-байтовой записи не разобрана: найдены два
поля из девяноста байт.

Логика поведения отдельного динозавра (ИИ, реакции, смена параметров во
времени) не разобрана вовсе — я дошёл только до места хранения.


## Раскладка записи вида (90 байт)

Собрано по всем 17 циклам с шагом `$5A`. Опознано 26 смещений из 90 байт;
смысл большинства не установлен, поэтому ниже только то, что видно.

| смещение | размер | что видно |
|---|---|---|
| `+$00` | long | адрес (берётся через `pea`) |
| `+$24` | long | указатель (`movea.l $24(a1),a2`) |
| `+$2A`, `+$2C` | word | читаются в расчётах |
| `+$34`, `+$3A` | word | слагаемые (`add.w $34(a1),d2`) |
| `+$3C` | byte | флаг (`tst.b`) |
| `+$3E`, `+$3F`, `+$40` | byte | читаются вместе |
| `+$42` | word | **устанавливается как значение + 144** |
| `+$44` | word | **дрейфует на ±1, см. ниже** |
| `+$46`, `+$48`, `+$4A`, `+$4C` | word | обнуляются при сбросе |
| `+$4D` | byte | состояние; `==2` у всех шести — особое условие |
| `+$4E` | word | `or.w $4E(a1),d2` — набор битов |
| `+$50` | word | часто пишется |
| `+$52`, `+$54` | long | указатели |
| `+$56`, `+$57` | byte | ставятся в `$FF` |
| `+$58` | byte | самое частое поле, 11 обращений |
| `+$59` | byte | читается |

## Как меняются параметры видов

Процедура на `$02FD36`-`$02FD94` проходит по всем шести записям и делает
две вещи.

**Первое.** Поле `+$42` каждого вида получает значение из массива в
структуре `a6` плюс 144 (`addi.w #$0090,d1`).

**Второе.** У каждого вида есть счётчик в массиве `$12(a6)`. Пока он не
ноль — уменьшается на 1. Как дошёл до нуля, перезаряжается из таблицы ROM
`$031D16` и поле `+$44` сдвигается на ±1:

```asm
loc_02FD5A:
	tst.w	(a0)              ; счётчик вида
	bne	loc_02FD92        ; не дошёл — просто уменьшить
	move.b	(a1),d1           ; перезарядка из $031D16
	move.w	d1,(a0)
	move.w	#$0001,d2
	cmpi.w	#$0002,d0         ; d0 — номер вида в цикле (5..0)
	bhi	loc_02FD76
	neg.w	d2                ; у трёх видов знак противоположный
loc_02FD76:
	cmpi.b	#$3C,$4(a6)       ; глобальное значение против 60
	bcs	loc_02FD8A
	neg.w	d2                ; и ещё раз по этому условию
	add.w	d2,$44(a3)
```

### Периоды: `$031D16` = `5, 9, 15, 15, 9, 5`

Симметрично. Крайние виды меняются втрое чаще средних.

### Кривые: `$031BA8`, три строки по 122 байта

Амплитуды **100, 60, 20**. В каждой 121 значение от −A до +A с уплотнением
у краёв — это синусоиды; последний байт 0 служит терминатором.

Читаются они зеркально:

```asm
	move.b	($0,a0,d0.w),d1   ; выборка по общей фазе d0
	move.w	d1,(a1)+          ; вперёд — как есть
	neg.w	d1
	move.w	d1,-(a2)          ; назад — с обратным знаком
	adda.w	#$007A,a0         ; следующая кривая
```

То есть три кривые разворачиваются в шесть значений: виды разбиты на три
пары, и внутри пары значения противоположны по знаку.

### Что это складывается

Шесть видов образуют три пары в противофазе, с амплитудами 100/60/20 и
периодами изменения 5/9/15. Похоже на циклический баланс экосистемы, где
подъём одного вида сопровождается спадом парного.

**Оговорка:** что именно означает поле `+$44` — численность, сила, что-то
иное — из кода не видно. Установлено, КАК оно меняется, но не ЧТО это.


## ПОПРАВКА: `+$44` — это координата, а не абстрактный параметр

Предыдущий раздел делал вывод про «циклический баланс экосистемы».
**Он неверен.** Найдя потребителей поля `+$44`, я увидел, что запись
используется для построения атрибутов спрайта Mega Drive:

```asm
	move.w	$28(a1),d4
	add.w	$46(a1),d4        ; Y = база + смещение
	move.w	d4,(a0)+          ; слово 1: Y
	move.b	d3,d4
	addq.b	#1,d3
	move.w	d4,(a0)+          ; слово 2: размер + link
	move.b	$56(a1),d4
	lsl.w	#4,d4             ; номер тайла × 16
	addi.w	#$0374,d4         ; база тайлов в VRAM
	andi.w	#$07FF,d4         ; 11-битная маска индекса тайла
	or.w	$2C(a1),d4        ; атрибуты
	move.b	$59(a1),d6
	ror.w	#3,d6             ; палитра и приоритет в старшие биты
	or.w	d6,d4
	move.w	d4,(a0)+          ; слово 3: тайл + атрибуты
	move.w	$2E(a1),d4
	add.w	$44(a1),d4        ; X = база + смещение
	move.w	d4,(a0)+          ; слово 4: X
```

Четыре слова в порядке Y, размер+link, тайл+атрибуты, X — это в точности
формат записи таблицы спрайтов. `andi.w #$07FF` (11 бит под индекс тайла) и
`ror.w #3` (перенос битов в поля палитры и приоритета) однозначны.
В другом месте встречается `addi.w #$0080` к `+$44` — каноническое
смещение координат спрайта на Mega Drive.

### Уточнённая раскладка

| смещение | назначение |
|---|---|
| `+$20` | счётчик, уменьшается |
| `+$22` | состояние, сравнивается с 1 |
| `+$28` | **база Y** |
| `+$2C` | атрибуты спрайта |
| `+$2E` | **база X** |
| `+$44` | **смещение X** |
| `+$46` | **смещение Y** |
| `+$50` | счётчик, уменьшается под флагом `+$58` бит 3 |
| `+$56` | номер тайла (умножается на 16) |
| `+$58` | флаги |
| `+$59` | палитра и приоритет |

### Что это значит для механики

Синусоиды с амплитудами 100/60/20 и периодами 5/9/15 управляют **колебанием
положения**, а не численностью видов. Зеркальное чтение даёт пары объектов,
качающихся в противофазе. Это анимация движения, а не баланс экосистемы.

Отсюда же следует, что 90-байтовые записи — это отображаемые объекты, а не
описания видов. Совпадение их числа с числом видов (шесть) меня и увело в
сторону; проверка `+$4D == 2` у всех шести сама по себе этого не доказывала.
