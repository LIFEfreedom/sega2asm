# Сценарии этапов по таймеру: автомат, проходы, подкрепления

Разбор кода покадровых сценариев (dyna #207, часть 2). Сводная таблица
всех 256 этапов — в [game-events.md](game-events.md), она собрана
эвристикой по листингу. Этот документ — то, как сценарии устроены на
самом деле. Данные для ремейка из этого разбора пишет
`tools/stageevents.py`, его зовёт `tools/exportmissions.py`.

## Где зовётся

Главный цикл увеличивает `GameTick` `$FFE05C` (`addq.l #1` по `$01630A`)
и сразу зовёт `RunStageFrameHook` `$02D090` (`$01631C`). Тот прыгает по
`table_stageframe` `$02D0B8` по байту `+$3` описания миссии. Первый тик
миссии — 1: `StartMatch` обнуляет `GameTick` (`$016568`).

Перед `StartMatch` раннер обнуляет весь блок `$FF0564…$FFEBFC`
(`$003A44`, `move.w #$EB98,d0` байт). В него входят счётчик этапа
`$FFE0BC`, флаг рыбалки `$FFE11F` и флаг «было» этапа 33 `$FFE0DF`, так
что каждая миссия начинает с нулей.

## Счётчик этапа

Счётчик у этапа один — `StageEventTimer` `$FFE0BC`, слово. Все общие тела
(`$02F1D2…$02F7BC`) ведут его одинаково:

```
если счётчик != 0:
    счётчик -= 1
    если счётчик == 0:  fire; счётчик = d6      (у тел «Once» — ничего)
иначе, если младшее слово GameTick > d7:
    start; счётчик = d6
```

Проверка старта — `move.l GameTick,d0; cmp.w d0,d7; bcc` (`$02F20E`):
сравнивается **младшее слово** тика, беззнаково и строго. Событие
начинается на первом тике после `d7`, а не на самом `d7`.

Тела различаются только тем, что делают `start` и `fire`:

| режим | что | тела |
|---|---|---|
| A | `start` только взводит счётчик; первое действие — через `d6` | `StageSeedType25Tick`, `StageSpreadType25Tick`, `StageSpreadTerrainTick`, `StageConvertInner14Tick`, `StageConvertAll14Tick`, `StageConvertWaveTick` (на старте только темнеет палитра) |
| B | `start` = `fire`: `bra.s` сразу в действие | `StageSpreadWideTick`, `StageSpreadType8Tick`, `StageQuakeSpreadTick` |
| C | своё действие на старте, потом периодическое | `StageSpreadRandomTypeTick`, `StageSpreadRandom89Tick`, `TickLavaEruption`, `StagePoisonTick` |
| D | действие один раз; на нуле счётчик перезаряжается без действия и нулём больше не бывает | `StageShudderTick`, `StageSoundLoopTick`, этапы 6 и 132 |
| E | «Once»: на нуле ничего, счётчик остаётся нулём, и на следующем тике тело стартует снова — период `d6 + 1` | `StageConvertInner14Once`, `StageConvertAll14Once` |

Кроме тел, счётчик пишут ИИ (`$026318`), `ResetEventTimer` `$02EB82` и
марш ﾒｶﾞｻﾞｳﾙｽ (`$02F0E4`).

События «на тике N» в самих сценариях — `cmpi.l #N,d0; bne` после
`move.l GameTick,d0`, то есть строгое 32-битное равенство.

## Проходы по местности

Общее соглашение: `d4` — маска типов (бит = тип 0…31, `btst d2,d4`),
`d5` — тип, в который красят. Тип клетки — младшие пять бит байта
`+1` клетки `TerrainMap`, растения и деревья — тоже типы. Обход — по
строкам, внутри строки по столбцам. Клетка, перекрашенная проходом,
остаётся позади: проход её не перечитывает, а `SpreadToNeighbours`
меняет у соседей только картинку, не тип.

| процедура | клетки | что |
|---|---|---|
| `SpreadTerrainRandom` `$0211BC` | 1…38 | тип из маски и `Random < $19` (25 из 256) — перекрасить |
| `ConvertTerrainInner` `$02123A` | 1…38 | тип из маски — перекрасить |
| `ConvertTerrainAll` `$0212A2` | 0…39 | тип из маски — перекрасить |
| `SeedEmptyTerrain` `$0210CE` | с (38, 38) назад до (1, 1) | тип ровно `d4`: бросок `Random < $40`; первая выигравшая клетка перекрашивается, обход кончается. Проигравшие не мешают идти дальше |
| `RepaintLastCellOfType` `$021150` | с (38, 38) назад | первая встреченная клетка ровно типа `d4` — перекрасить, обход кончается |
| `RepaintOneRandomCellOfType` `$02104C` | 1…38 вперёд | как `SeedEmptyTerrain`, но вперёд; сценарии этапов её не зовут |
| `SpreadTypeMapWide` `$020EF0` | 1…38 | первый обход: у каждой клетки типа `d5` взвести бит 2 `CellFlagMap` восьми соседям, чей тип **не** в маске `d4`; второй обход: взведённое перекрасить в `d5` (и бит снять). Соседи того же типа тоже перекрашиваются. Биты на кольце 0/39 взводятся, но их никто не красит и не снимает |
| `PlaceTerrainListFiltered` `$02FB0A` | список | каждую клетку списка расстановки (формат `LoadPlacement`) перекрасить в `d5` |

Взвешенный выбор типа — `StageSpreadRandomTypeTick` `$02F32E` и
`StageSpreadRandom89Tick` `$02F3B2`: один `Random` на срабатывание,
**до** прохода. Меньше `$80` — тип 8, затем меньше `$50` — тип 9, иначе
тип 5: 128, 80 и 48 из 256.

`SeedEmptyTerrain` в [game-events.md](game-events.md) раньше
описывалась как «только пустые клетки, 25%»; на деле это один
конкретный тип (у всех сценариев 24 → 25) и 64 из 256 на клетку.

## PaintTerrainCell `$020768`

Перекраска одной клетки:

- `$0203DE` — **таблица в ROM**, а не байт RAM: тип → хранимый байт
  `+1` клетки, пять младших бит — тип, старшие — флаги. Вода (19)
  хранится как `$53` — та самая «плитка `$53`» рыбалки ﾌﾟﾃﾗ.
- байт `+0` — счётчик роста: `TerrainCounterSeeds[тип]` `$02246C` плюс
  `(Random & 7) - 3`;
- картинка клетки: тип 8 и типы маски `TerrainSpreadMask` зовут
  `SpreadToNeighbours`, прочие берут байт из таблицы записи `$FFBCBC`;
- `TerrainAffectUnitsOnCell`: оба слота `UnitMap` клетки идут по
  `TerrainEffectTable` `$02098E`:

| новый тип | действие |
|---|---|
| 11, 12, 30 | `DieUnlessAction27` |
| 13 | `FissureSwallowUnit` |
| 19 | `TerrainType19Effect`, по **действию** юнита `+$15`: `$01` гибнет; `$04…$09`, `$14…$18`, `$26`, `$27`, `$29`, `$31` гибнут со всплеском; идущих возвращает и разворачивает |
| 20 | `DieIfActionAllows` |
| 2…4, 6, 7, 21 | ничего |
| прочие | `StopGrazingHere` |

Флаг `$FFE11F` («рыбы больше нет») ставит **только**
`StageSpreadWideTick` (`st $FFE11F` по `$02F204`), не сама
`SpreadTypeMapWide`: поток края этапа 31 и `StageQuakeSpreadTick` рыбалку
не трогают. Читает флаг только `RuleGrazeTile53` `$018334`; у
`RuleGrazeTile53Full` вида 13 проверки нет.

## Особые этапы

**Этап 6 (Story 37).** Своё тело на том же счётчике (`$02DAFE…$02DB98`),
режим D со счётчиком `$FF`: один раз после тика 9000. Пять
`SpreadTerrainRandom` края (тип 30) в 24, 4, 3, 2, 7 — только внутри
поля; затем `ConvertTerrainAll` 30 → 0 по всей карте; затем клетки
списка `data_231` `$02DB9A` → 0; затем `LoadPlacement` по **тому же**
списку: 12 ﾎﾟﾝﾎﾟﾝ (тип 50, вид 11). Этап 132 устроен так же (после
4500, `$02E7E6`, 19 записей), но его не берёт ни одна миссия.

**Этап 31 (Story 34).** Две фазы на одном счётчике (`$02DC1E…$02DD44`):

- тик < 8000: порог 30, период 900, раз в период дважды
  `RepaintLastCellOfType` 26 → 25. Взведя счётчик, тело проваливается в
  код второй фазы и там же уменьшает его на один, поэтому первое
  срабатывание — на тике 930;
- тик == 8000: счётчик обнуляется (`clr.w $FFE0BC`);
- тик > 8000: порог 8100 — `ConvertTerrainAll` 19 → 30, затем раз в
  1800 тиков `SpreadTypeMapWide` края 30, кроме типов 14, 27, 28, 29, 31.

**Этап 33 (Story 15).** Кроме `StageConvertWaveTick` (13500/600): если
`$FFE0DF` = 0, `GameTick & $3FF` = 0 и перепись вида 4 игрока 1
(`$FFE089`) не меньше 2 — `ConvertTerrainInner` 19 → 8 и `st $FFE0DF`.
`$FFE0DF` пишет ещё ИИ (`$02B176`, `$02B1C2`, `$02B260`).

**Этап 117 (Extra 21).** `StageSpreadRandomTypeTick` с порогом 5400
(`move.l`, но сравнение то же `cmp.w`), на тике 12600
`ConvertTerrainInner` 19 → 8, на тике 5400 — подкрепление.

**Этап 38 (Story 40).** Пока тик ≤ 12600 и стегозавров игрока 2
(`$FFE096`) не больше двух, `GameTick` принудительно ставится в 12600:
часы прыгают. Не выгружается.

## Подкрепления

Все нейтральные, игроков среди них нет. Формат записи — как у
`LoadPlacement` `$01EA12`; запись на клетке типов 22…30 (маска
`$7FC00000`) пропускается — по местности **на момент вызова**.

| этап (миссия) | тик | данные | записей | тип → вид |
|---|---|---|---:|---|
| 4 (Story 9) | == 6450 | `$02D322` | 1 | 58 → вид 20 |
| 10 (Story 38) | == 5400 | `$02D458` | 10 | 51 → вид 12 |
| 35 (Story 20) | == 9005 | `$02D8C8` | 6 | 58 → вид 20 |
| 6 (Story 37) | > 9000, раз | `$02DB9A` | 12 | 50 → вид 11 |
| 117 (Extra 21) | == 5400 | `$02E4EC` | 32 | 58 → вид 20 |
| 132 (нет миссии) | > 4500, раз | `$02E7E6` | 19 | 50 → вид 11 |

## Что выгружается для ремейка

`tools/stageevents.py` разбирает код сценария (незнакомый код —
остановка) и пишет в `map.events`:

- `timers` — `after` (`d7`), `period` (`d6`), `arm` (что грузится на
  старте; у первой фазы этапа 31 — 899), `rearm: false` у тел «Once»,
  окна `above`/`below` у этапа 31, списки `start` и `fire`;
- `ticks` — `tick` (равенство) либо `every` с `when` и `once` (этап 33);
- операции: `spread_random`, `convert_inner`, `convert_all`, `seed_one`,
  `repaint_last`, `spread_neighbours`, `paint_cells`, `place`,
  `stop_fishing`, `reset_timer`, `music`. Числа читаются из самих тел с
  проверкой кода инструкции.
- смена музыки (dyna #231) — `jsr PlaySound` `$00DFEE` с `move.b #m,d0`
  в блоке «на тике»: операция `{"pass": "music", "music": m}`, m — номер
  `table_music`. Так меняют трек 35 сценариев; 34 из них берут миссии
  (у этапа 17 блок стоит за пожаром и разбирается отдельно,
  `MUSIC_EXTRA`), этап 132 не берёт ни одна.

Не выгружается, у каждого своя задача ремейка: лава (`TickLavaEruption`,
#142), яд (`StagePoisonTick`, #188), пожар под случайным стоящим юнитом
игрока 1 (этапы 12, 17, 223), марш ﾒｶﾞｻﾞｳﾙｽ (этапы 20 и 37, #209),
подсказки уроков (51…58, #68), прыжок часов этапа 38, звуковые сцены,
палитры, тряска, камера и текст. `StageSoundLoopTick` `$02F7BC` звука сам
не заводит: раз за миссию он зовёт `RefreshScreenKeepFlags` — сцену
`EventAnimBig` со своими звуками (перепись —
[game-sound-events.md](game-sound-events.md)). Список по миссиям — в `report.md` выгрузки.

Ремейк не повторяет: генератор случайных чисел оригинала (броски идут
из своего, в том же порядке), счётчики роста клеток (высыхание болота —
dyna #147), всплеск идущих юнитов на новой воде (dyna #202). Яйца на земле
и туши на новой воде гибнут.

## Ошибки, найденные в game-events.md

- `d7` описывался как тик начала; на деле начало — первый тик **после**
  `d7`, и сравнивается младшее слово.
- `SeedEmptyTerrain` — не «пустые клетки, 25%», а один тип, 64 из 256.
- «10%» у `SpreadTerrainRandom` — округление 25/256.
- `StageSpreadWideTick`, `TickLavaEruption`, `ScrollToClampedCell`,
  `StageBurnRandomUnitCell`, `PlaceTerrainListFiltered` описывались как
  «местность не трогают»; все они её красят.
- Генератор обрезал список вызовов до четырёх, поэтому у этапов 6, 31 и
  117 пропадали проходы и подкрепление; исправлено.
