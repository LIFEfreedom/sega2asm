# Разбор Dyna Brothers 2 — сводная карта

Указатель по документам и сведённые в одно место раскладки структур.
Подробности и доказательства — в тематических файлах; здесь только итог.

Всё найденное проверяется одним способом: после каждого изменения имён
проект пересобирается и сверяется с оригиналом по SHA-1. На момент
написания сборка побайтовая.

## Запись юнита — 48 байт, массив `$FF5F4E`

Размер доказан дважды: `mulu.w #$0030` в `$01538C` и `lea $30(a2),a2` в
главном цикле. Индекс байтовый, всего 255 слотов плюс нулевой.

| смещение | размер | что |
|---|---|---|
| `+$00` | байт | тип; ноль означает свободный слот |
| `+$02` | байт | клетка X |
| `+$03` | байт | клетка Y |
| `+$07` | байт | анимация |
| `+$08` | байт | счётчик кадров анимации, +1 каждый кадр |
| `+$09` | байт | владелец: `>0` игрок 1, `<0` игрок 2, `0` нейтральный |
| `+$0A` | слово | индекс клетки на картах |
| `+$0C` | байт | вид в младших 5 битах, плюс флаги в битах 5 и 7 |
| `+$11` | байт | флаги; **бит 5 — постоянное улучшение** |
| `+$14` | байт | таймер действия; на нуле — пересмотр поведения |
| `+$15` | байт | текущее действие |
| `+$16` | **слово** | **текущие очки здоровья** |
| `+$18` | слово | готовое байтовое смещение в таблицу дескрипторов |
| `+$1A` | слово | категория: биты 0–9 класс, 13 падаль, 14 и 15 стороны |
| `+$1C` | байт | бит 0 и 1 — пороги здоровья, бит 4 — занят |
| `+$1E` | байт | накопитель перемещения, +32 за тик |
| `+$1F` | байт | стоимость шага по текущей местности |
| `+$20` | байт | номер партнёра по стычке |
| `+$24` | байт | направление 0–7, нечётные — диагонали |
| `+$26` | байт | таймер падали, стартует с 30 |
| `+$28` | байт | битовые флаги по номеру игрока (биты 4–7) |
| `+$29` | байт | степень удара; **пишется, но никем не читается** |

Не опознаны: `+$01`, `+$04`–`+$06`, `+$0D`, `+$10`, `+$12`, `+$13`, `+$17`,
`+$1D`, `+$21`–`+$23`, `+$25`, `+$27`, `+$2A`–`+$2F`.

### Разбиение массива по владельцу

| база | слотов | счётчик свободных |
|---|---|---|
| `$FF5F7E` | 7 | `$FFE042` |
| `$FF60CE` | 100 | `$FFE043` |
| `$FF738E` | 40 нейтральных | `$FFE044` |
| `$FF7B0E` | 100 | `$FFE045` |
| `$FF8DCE` | 7 | `$FFE046` |

Итого 254 плюс нулевой слот — ровно столько проходов делает главный цикл.

## Блок параметров вида — 326 байт

Путь до него: `+$18` юнита — байтовое смещение в таблицу дескрипторов
`$01FC5A`, по смещению 0 дескриптора лежит указатель на блок.
**Раскладка закрывается без остатка**, что подтверждает независимо
измеренный шаг блоков.

| смещение | размер | что |
|---|---|---|
| `+$04` | слово | максимум здоровья |
| `+$06`, `+$08` | слова | два порога здоровья |
| `+$0A`, `+$0C`, `+$0E`, `+$10` | слова | сила удара по степеням 0–3 |
| `+$3A`…`+$4F` | 22 байта | **таблица A**: стоимость шага по местности |
| `+$50`…`+$7B` | 22 слова | **таблица B**: урон от местности, состояние `$32` |
| `+$7C`…`+$A1` | 19 слов | **таблица C**: урон от местности, состояние `$0F` |
| `+$AC` / `+$AD` | байты | шанс редкого исхода боя, из 256 |
| `+$AE` / `+$AF` | байты | доля проходящего урона, из 256; меньше — лучше |
| `+$B8`…`+$BB` | байты | четыре степени, попадают в `+$29` цели |
| `+$BD` | байт | награда убийце |
| `+$BE` | слово | ценность погибшего |
| `+$C4`…`+$CA` | слова | сила удара улучшенного |
| `+$CE`, `+$D0`, `+$D2`, `+$D4` | слова | пороги размножения |
| `+$D8`…`+$13F` | 104 байта | те же три таблицы для улучшенного |

Парные поля выбираются битом 5 байта `+$11` юнита. Табличные пары сдвинуты
ровно на `$9E`, скалярные лежат рядом.

## Состояние игрока — 86 байт

`Player1State` = `$FF9C84`, `Player2State` = `$FF9CDA`, шаг `$56`.
`CurrentPlayerPtr` = `$FF9C7E`.

| смещение | размер | что |
|---|---|---|
| `+$02` | длинное | деньги, двоично-десятичные |
| `+$06` | байт | число травоядных (виды 1, 2, 7) |
| `+$07` | байт | число хищников (виды 3, 4, 5, 8, 9, 10) |
| `+$08` | байт | число вида 6 |
| `+$0F` | байт | режим или стадия, сравнивается с 9 |
| `+$1A` | слово | накопленная награда за убийства |
| `+$1C` | слово | смещение выбранного юнита в массиве |
| `+$1E` | байт | класс здоровья выбранного юнита, 1–6 |
| `+$26`…`+$2F` | 10 байт | перепись по видам 1–10 |
| `+$42` | слово | потери, с потолком 999 |

## Как всё связано

Главный цикл `$016976` каждый кадр проходит 255 слотов, двигая и анимируя
живых. Когда таймер `+$14` юнита добегает до нуля, вызывается пересмотр
поведения: две таблицы самоотносительных переходов выбирают по действию
`+$15`, а затем по виду, скрипт — список правил по приоритету.

Правила ведут к трём исходам, замыкающим пищевую цепь: травоядные едят
местность, хищники едят падаль, а погибший становится падалью на 30 тиков.
Размножение требует здоровья **выше** видового максимума, что возможно
потому, что лечение насыщается в `$FFFF`, а не в максимуме.

Стычка разрешается двумя бросками: первый решает, случится ли редкий исход
(у неулучшенного 1 из 256), второй делит обычные исходы на три. Урон —
сила нападающего по степени, умноженная на долю цели и делённая на 256.

## Крупные поправки по ходу разбора

Три вывода пришлось отменить, и все три — по одной причине: смысл
строился по месту записи, а не по потребителям.

| было | стало |
|---|---|
| `+$44` — параметр вида, синусоиды как баланс экосистемы | координата спрайта, синусоиды как анимация |
| «таблицы цен» на `$022550` | это внутренности блоков параметров; цены в голове `data_173`, в BCD |
| растения — виды 7–10 | растения вообще не юниты, а тайлы карты |

Плюс две помельче: байт `+$0` шаблона типа оказался не номером картинки,
а категорией, и три `nop` в таблице поведения оказались не вырезанным
кодом, а нормой для состояний, которыми занят другой диспетчер.

## Что осталось

- Типы местности 11, 12, 13, 20 — непроходимы и смертельны, но чем они
  являются, неизвестно.
- Назначение карты `$FFD200`.
- Какой тайл соответствует какому из четырёх названий растений.
- Мясо или яйца у вида 26.
- Зачем нужно `+$29`, если его никто не читает.
- Смысл большинства действий `+$15` ниже `$0B`.
