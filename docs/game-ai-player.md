# Компьютерный противник

До этого захода во всех документах разбиралось поведение **динозавров**.
Логика второго игрока, когда им управляет машина, не упоминалась нигде.
Найти её удалось тем же признаком, которым написана вся поведенческая
часть игры: **список правил по приоритету**.

## Приём один и тот же

Цепочка подпрограмм, каждая возвращает «сделал» или «не сделал»,
вызывающий останавливается на первой сделавшей:

```asm
	bsr.w	Правило
	bne.w	выход
```

Поиск таких цепочек механический (`make chains`), и он даёт **37 штук на
всю игру**: двадцать девять в `code_137` — это скрипты видов, разобранные
в [game-ai-behaviours.md](game-ai-behaviours.md), — одна в `code_215`, и
семь в `data_207`, которые нашлись позже, когда анализатор научился
засевать обход указателями из таблиц данных. Это и есть цепочки фаз
противника, о них раздел ниже.

## Цепочка противника — `$02B274`

```asm
Sub_02B274:
	move.b	($FFE0B3).l,d3      ; сохранить фазу
	move.b	#$01,($FFE0B3).l
	bsr.w	AiPlanForPhase  ; выбрать план, a3 = запись плана
	bsr.w	Sub_029862 / bne    ; яйцо вида 3
	bsr.w	Sub_02981A / bne    ; яйцо вида 2
	bsr.w	Sub_0297D2 / bne    ; яйцо вида 1
	bsr.w	Sub_0298A2 / bne    ; яйцо вида 4
	bsr.w	Ai_0298E2  / bne    ; яйцо вида 5
	bsr.w	Ai_029922  / bne    ; яйцо вида 6
	move.b	d3,($FFE0B3).l      ; вернуть фазу
```

Шесть правил, и все шесть делают **одно и то же действие — кладут яйцо**.
Порядок перебора не по номеру вида, а по приоритету: **3, 2, 1, 4, 5, 6**.

## Правило устроено одинаково

```asm
Sub_029862:                     ; правило «вид 3»
	move.b	$2D(a5),d7          ; общий счётчик фазы
	beq.w	класть              ; ноль — класть без оглядки
	cmpi.b	#$04,d7
	bcc.w	класть              ; четыре и больше — тоже
	move.b	$12(a5),d7          ; сколько уже есть вида 3
	cmp.b	$6(a3),d7
	bcc.w	мимо                ; норма выбрана — правило молчит
класть:
	move.w	#$0003,d0
	bsr.w	TestIndexBitThenCall
```

То есть: **пока своих динозавров этого вида меньше нормы — класть яйцо**,
а при `$2D(a5)` вне диапазона 1…3 норма игнорируется вовсе.

Поля раскладываются без остатка: `$10`…`$15` состояния сессии — сколько
каких видов у игрока сейчас, `+$04`…`+$09` записи плана — сколько
полагается. Соответствие видов и полей строго по порядку.

## Разрешения проверяет общий шлюз

```asm
TestIndexBitThenCall:           ; $02B524
	tst.b	($FFE0B3).l
	beq.w	делать              ; в нулевой фазе без проверок
	move.b	($FFE0DD).l,d7
	not.b	d7
	btst	d0,d7
	beq.w	мимо
делать:
	jsr	(Player_02391A).l       ; положить яйцо вида d0
```

`$FFE0DD` — маска запрещённых команд, и бит проверяется **после
инверсии**, то есть действие проходит, только если его бит сброшен. Так
противник соблюдает ограничения миссии: список разрешённых команд у
каждой свой ([game-missions.md](game-missions.md)).

`Player_02391A` `$02391A` берёт номер вида, считает `(вид − 1) × 4` и
индексирует `CostsEggs` `$022374` — цену яйца. Дальше обычная оплата.

## Какую цепочку правил взять — решает соотношение сил

`AiPickChain` `$02B8BC` (двадцать площадок вызова) кладёт в `a6` цепочку
правил, которую противник будет разбирать. Выбор из двух шагов.

**Сначала — не навязана ли цепочка.** Если длинное `+$64` состояния сессии
не ноль, оно и берётся, без всяких вопросов. Так скрипт может заставить ИИ
играть по своей цепочке.

**Иначе — по обстановке.** `AiSituationCode` `$02B8EE` считает два итога
через `CensusTotals` `$02B966`:

```asm
	d1 = сумма +$0..+$5 сессии    ; перепись игрока 1 по шести видам
	d2 = сумма +$10..+$15         ; перепись игрока 2, то есть ИИ
```

Что это именно перепись, видно со стороны писателя: `CensusCountUnit`
`$01D6AC` выбирает половину по знаку владельца `+$9` — положительный ведёт
на `+$0`, отрицательный на `+$10`.

Дальше шесть исходов:

| условие | код |
|---|---|
| у обоих 25 и больше | 0 |
| ИИ впереди (или у него 25+), у игрока 5…24 | 1 |
| ИИ впереди, у игрока 1…4 | 2 |
| ИИ впереди, у игрока **никого** | 3 |
| ИИ не впереди, у игрока 5 и больше | 4 |
| ИИ не впереди, у игрока меньше 5 | 5 |

Код индексирует шесть длинных слов на `+$80` состояния сессии — по
указателю на цепочку каждому положению.

То есть у противника **шесть режимов игры**, и переключается он между ними
не по фазе и не по времени, а по тому, кого сейчас больше. Пороги грубые:
двадцать пять юнитов и пять юнитов, больше ничего. Фазовая машина
(`AiPhaseStep`) при этом работает своим чередом и решает другой вопрос —
какие правила внутри цепочки сейчас включены.

## Три набора правил, 28 площадок

Тем же шлюзом пользуются ещё два набора. Отличаются они тем, с чем
сравнивают счётчик:

| набор | адреса | счётчик | норма |
|---|---|---|---|
| A | `$0297D2`–`$029946` | `$10`…`$15(a5)` | `+$04`…`+$09(a3)` — запись плана |
| B | `$029A54`–`$029BBC` | `$10`…`$15(a5)` | `+$00`…`+$05(a5)` — прямо в сессии |
| C | `$029BF8`–`$029C70` | `$12`…`$14(a5)` | нормы нет |

Плюс девять одиночных площадок в `$026216`–`$0299B4`. Набор A заводит
цепочка `$02B274`, а **наборы B и C зовут скрипты миссий** — из
`$0270xx`–`$0277xx`, положив перед вызовом маску фаз в `d7`, как и всякое
другое правило скрипта ([game-ai-missions.md](game-ai-missions.md)).
Отдельного диспетчера у них нет.

## План берётся по таблице

`AiPlanForPhase` `$029754`:

```asm
	lea	(Player2State).l,a4     ; ИИ — это второй игрок
	movea.l	(MainStatePtr).l,a6
	move.b	$3(a6),d7               ; индекс
	lea	AiPlanTable(pc),a6
	add.w	d7,d7
	move.w	($0,a6,d7.w),d7
	adda.w	d7,a6                   ; самоотносительное слово
	lea	(SessionState).l,a5
```

`AiPlanTable` `$02BC3C` (`data_215`) — **64 самоотносительных слова**, и
все 64 разрешаются внутрь сегмента, то есть таблица полная. За ними
**36 различных записей по `$3C` байт**; часть индексов делит запись на
двоих (0 и 1 ведут на `$02BE3C`, 6 и 10 — на `$02CE2C`). Раскладка
записи разобрана ниже, в разделе про фазы.

## Весь набор команд, а не одни яйца

Цепочка правил — не всё, чем занят противник: яйца идут через шлюз
`TestIndexBitThenCall`, а остальные команды вызываются напрямую. Найти их
можно с другого конца — по кошельку. Из кармана второго игрока платят
двенадцать процедур (`PayCost2` `$024ABA`), и почти все зовутся из
`code_214`, то есть из кода противника:

| команда | площадок вызова | откуда зовут |
|---|---|---|
| эффект 4 (засуха) | 13 | `code_214` |
| **эффект 1 (за 50, на динозавра)** | **10** | `code_214` |
| ливень | 5 | `code_214` |
| буря | 4 | `code_214` |
| эффект 5 | 4 | `code_214` |
| растения | 3 | `code_214` |
| молния | 2 | `code_214` |
| эффект 7 (метеорит) | 2 | `code_214` |
| переделка | 1 | `code_214` |
| яйцо | 1 | цепочка `$02B274` |
| команда за 206 | 1 | `code_214` |
| наведение | 1 | **не из кода противника** |

Итог: **противник пользуется всем, кроме наведения**. Причём самая
затасканная у него не самая грозная, а самая дешёвая: у команды за 50
единиц десять площадок вызова, больше чем у ливня, бури и метеорита
вместе взятых. Засуха с её тринадцатью — того же порядка.

Наведение выпадает не случайно: единственный вызов его платной части
идёт из `$017B36`, то есть из слоя поведения динозавров, а не из слоя
команд. Это поштучное списание, пока кого-то ведут, и к решениям
противника отношения не имеет.

Яйца при этом устроены сложнее прочего — с планом, нормами и шлюзом
разрешений, — а погодные команды вызываются россыпью по условиям прямо
в `code_214`. Разбор этих условий не делался.

## `code_214` — по каким признакам он выбирает команду

Сегмент `$029A54`–`$02AF46`, шестьдесят четыре процедуры. Тридцать три из
них выдают команду, и делятся они на три вида, различающиеся тем, как
задан признак.

### Погодные: маска местности и порог

Самый прямой вид. Правило опрашивает карту, считает клетки, попадающие в
битовую маску типов местности, и действует, если их набралось не меньше
порога:

```asm
Ai_02A22C:                          ; ливень
	bsr.w	TestPhaseMask           ; работает ли правило в текущей фазе?
	jsr	(Player_024EC0).l           ; её сейчас можно применить?
	...
	move.l	#$000000F8,d7           ; маска: типы 3,4,5,6,7
	jsr	(PlayerLoop_0221EC).l       ; сосчитать такие клетки
	cmpi.b	#$12,d7
	bcs.w	мимо                    ; меньше восемнадцати — не лить
```

Все найденные маски и пороги:

| правило | команда | типы местности | порог |
|---|---|---|---|
| `$02A22C` | ливень | 3, 4, 5, 6, 7 | 18 |
| `$02A2AA` | ливень | 8, 9 | 2 |
| `$02A39A` | буря | 19, 20 | 18 |
| `$02A418` | буря | 24, 25, 26 | — |
| `$02A568` | засуха | 0…7 | 29 |
| `$02A5EA` | засуха | 16 | 21 |
| `$02A64C` | засуха | 16 | 21 |
| `$02A69C` | засуха | 14 | 18 |
| `$02A9D8` | засуха | 1…7 | 8 |
| `$02AA6C` | засуха | 21, 22, 23 и 21, 22 | — |
| `$02A4EE` | засуха | — | 18 |
| `$02AAF6` | засуха | — | 3, 18 |
| `$02A94E` | растения | — | 21 |

То есть противник **терраформирует по счёту клеток**: набралось много
сухой земли — льёт, много сырой — сушит. Засуха у него самая частая не
случайно: под неё подведено шесть разных признаков против двух у ливня.

### Команда за 50: признак вместо маски

Десять правил `$029E3C`–`$02A0F2` устроены иначе. Вместо маски они
передают обходчику карты **процедуру-признак**, и она решает по каждой
клетке сама:

```asm
Unit_029E3C:
	lea	(Map_029EB4).l,a3           ; признак клетки
	bsr.w	MapLoop_02B600              ; обойти карту, d7 = сколько подошло
	cmp.w	d0,d7
	bcs.w	мимо                        ; не набралось
	jsr	(CastWateringP2).l           ; команда за 50
```

Ни `TestPhaseMask`, ни маски местности здесь нет: это правило работает в
любой фазе.

Десять правил — но не десять признаков. Они складываются всего из
**четырёх проверок клетки**, взятых в двух вариантах и по двум областям
обхода.

Проверки (`code_170`, все читают тип из младших пяти бит плитки):

| проверка | что требует |
|---|---|
| `$020BFE` | байт `+$1` нулевой, и ни клетка, ни соседняя сверху не типов 3, 4, 7 |
| `$020C2A` | тип 17 или 18 |
| `$020C42` | тип 1, 2 или 5 |
| `$020C56` | плитка ровно 12 |

Вариантов два. `CellNearP2AndNot347`, `CellNearP2Type1718` и
`CellNearP2Type125` вдобавок требуют, чтобы **рядом стоял живой юнит
второго игрока** — та же `CellNearPlayer2Unit` `$01E1D6`, что и у полива:
клетка или любая из восьми соседних. `CellNot347`, `CellType1718`,
`CellType125` и `CellTile12` берут ту же проверку местности без этого
условия.

**Поправка.** Раньше здесь стояло «клетка свободна от юнита», и первые
три назывались `CellFree*`. И то и другое наоборот: `CellNearPlayer2Unit`
возвращает Z, когда юнит **есть**, а вызывающий считает клетку только при
Z. Символы переименованы в `CellNearP2*`.

Областей обхода тоже две, и в этом смысл приставок в именах:

* `MapLoop_02B600` считает вокруг точки `$24`/`$25` состояния сессии;
* `MapLoop_02B662` — вокруг координат юнита `$2`/`$3(a2)`, со сдвигом на
  клетку вверх и влево.

Порог в самих правилах не задан: они сравнивают счёт с `d0`, который
приходит снаружи — из слоя фаз, разобранного ниже.

Самая ходовая проверка — `$020C2A` (типы 17 и 18): её берут четыре
правила из десяти, каждое со своей подготовкой (`Unit_01E3BE`,
`Sub_01E3E6`, `Unit_01E422`) и, стало быть, со своим набором юнитов.

### Яйца: план и нормы

Третий вид разобран выше — он единственный со своей цепочкой, планом из
таблицы и шлюзом разрешений.

### Что это говорит о противнике

Он не строит стратегию, а **реагирует на состояние карты**: каждое правило
— это «если такого-то стало слишком много, применить такую-то команду».
Порядок проверок задаёт приоритет, порогов всего дюжина, и почти все они
лежат между 8 и 29 клетками.

## Скрипты ИИ миссий

Что противник делает **на конкретной карте**, задаёт отдельный слой:
таблица `AiScriptTable` `$0252EE` по номеру этапа (байт `+$3` описания
миссии — тот же индекс, которым берётся и `AiPlanTable`). Разбор всех
35 скриптов — в [game-ai-missions.md](game-ai-missions.md), `make
aiscripts`.

Оттуда же поправка к разделу ниже: `TestPhaseMask` `$02AEB8` проверяет
**не разрешение миссии**, а `btst` номера фазы `$FFE0B3` в маске `d7`.
То есть скрипт миссии — это список правил, расписанный по фазам роста:
в фазах 1–2 противник только льёт дождь, в фазе 3 у него открывается вся
погода, в фазах 4–5 добавляются метеорит и команды.

## Слой фаз: такт, план, порог

Всё предыдущее описывало **правила**. Осталось объяснить, кто их
запускает и откуда берутся числа, с которыми они сравнивают счёт. Это
один слой между главным циклом и `code_214`, и он разложен на шесть
ступеней.

### 1. Точка входа — `AiLoop_025282` `$025282`

```asm
	st	$4E(a5)                     ; «ИИ думает»
	subq.b	#1,$21(a5)              ; такт хода
	bge.w	пропустить              ; ещё не пора
	bsr.w	AiCapacityRecheck
	move.w	$22(a5),d2
	cmpi.w	#$0020,d2
	bhi.w	дальше
	bsr.w	AiMeasureTerritory      ; территории мало — пересчитать
дальше:
	move.b	#$01,$21(a5)            ; по умолчанию через кадр
	movea.l	(MainStatePtr).l,a6
	move.b	$3(a6),d7               ; номер миссии
	...
	jsr	(AiScriptTable,pc,d5.w)     ; скрипт ИИ этой миссии
```

`$21(a5)` — обратный счётчик до следующего решения, `AiScriptTable`
`$0252EE` — самоотносительные слова «миссия → скрипт».

### 2. `$22(a5)` — это размер территории

Раньше смысл поля был неясен. `AiMeasureTerritory` `$02B9CE` получает его
**заливкой от гнезда противника**: `FloodFillTerritory` `$02BA54` идёт по
четырём соседям, пропуская клетки по маске `$FFFFFF01` (то есть ходит
только по типам 1…7), и возвращает число закрашенных клеток.

Отсюда два порога, которые раньше выглядели произвольными:

* `AiNestOverCapacity` `$02B6DC` запрещает класть яйцо, когда
  `(динозавров видов 1 и 2 + 1) × 7 > $22(a5)` — **семь клеток пастбища
  на голову**;
* `AiScanUnitsP0` работает только при `$22(a5)` от 1 до 14, то есть когда
  противник заперт на пятачке.

### 3. Фазовая машина — `AiPhaseStep` `$0293DC`

Скрипт миссии кладёт в `a0` свою таблицу из шести длинных слов и зовёт
`AiPhaseStep`. Тот собирает три числа —

| | что считает |
|---|---|
| `d0` | своих динозавров видов 1 и 2 (`$FFE096`+`$FFE097`) |
| `d1` | своих динозавров видов 1…6 (`$FFE096`…`$FFE09B`) |
| `d4` | динозавров **человека**, видов 1…6 (`$FFE086`…`$FFE08B`) |

— и по текущей фазе `$2D(a5)` прыгает в `AiPhaseRules` `$02946A`:

| фаза | условие | новая фаза |
|---|---|---|
| 0 | `d0 >= 2` | 1 |
| 1 | нормы фазы 1 выбраны (`AiQuotaMetP1`) или `d4 >= 15` | 2 |
| 1 | иначе — по порогу `+$2A`/`+$2B`/`+$2C` | 3 |
| 2 | `d0 >= +$2A`, `d1 >= +$2B`, деньги `>= +$2C` | 3 |
| 3 | `d0 >= +$30`, `d1 >= +$31`, деньги `>= +$32` | 4 |
| 3 | иначе, если `d0 < +$2A` или `d1 < +$2B` | назад в 1 |
| 4 | `+$36`, `+$37`, `+$38` | 5 |
| 4 | иначе, если `d0 < +$30` или `d1 < +$31` | назад в 3 |
| 5 | `d0 < +$36` или `d1 < +$37` | назад в 4 |

Фаза одна на игру и **умеет откатываться**: потерял стадо — вернулся на
шаг назад. Заметить стоит и то, что на человека смотрит только фаза 1:
пока у игрока меньше пятнадцати динозавров, противник не торопится.

Дальше общий хвост `AiPhaseApply` `$029536`:

```asm
	move.b	d3,$2D(a5)                  ; новая фаза
	move.w	(AiPhaseOffsets,pc,d7.w),d7
	lea	($0,a6,d7.w),a3                 ; подзапись этой фазы
	move.l	a3,$42(a5)
	move.b	$0(a3),$21(a5)              ; такт
	move.b	$2(a3),$41(a5)
	movea.l	($0,a0,d7.w),a0
	jsr	(a0)                            ; цепочка этой фазы
```

Вот откуда `a3`, на который ссылаются все правила яиц: это **подзапись
текущей фазы**, а не запись целиком.

### 4. Запись плана разобрана до байта

`AiPhaseOffsets` `$029568` даёт шесть смещений — `$00`, `$04`, `$0E`,
`$18`, `$22`, `$26`. Отсюда вся раскладка `$3C` байт:

| смещение | что |
|---|---|
| `+$00`…`+$03` | подзапись фазы 0 |
| `+$04`…`+$0D` | подзапись фазы 1 |
| `+$0E`…`+$17` | фазы 2 |
| `+$18`…`+$21` | фазы 3 |
| `+$22`…`+$25` | фазы 4 |
| `+$26`…`+$29` | фазы 5 |
| `+$2A`, `+$2B`, `+$2C` | порог перехода: свои виды 1–2, свои 1–6, деньги |
| `+$30`, `+$31`, `+$32` | второй порог |
| `+$36`, `+$37`, `+$38` | третий порог |

Подзапись фазы:

| смещение | что |
|---|---|
| `+$0` | такт `$21(a5)` — через сколько кадров следующее решение |
| `+$1` | не читается ни одной найденной командой |
| `+$2` (слово) | бюджет: сколько юнитов или шагов карты успеть за ход |
| `+$4`…`+$9` | нормы по шести видам (есть только у фаз 1, 2, 3) |

Числа сходятся с игрой. Фаза 0 у всех 36 записей одинакова —
`01 01 00 01`: думать каждый кадр, обработать одного юнита. Фаза 1 —
`02 01 00 0A`: через кадр, десять юнитов. Фаза 3 — `06 C0 00 01` или
`03 40 00 05`: реже, но с нормами на все шесть видов. Пороги денег лежат
в ДВОИЧНО-ДЕСЯТИЧНОМ виде, как и цены: `00 00 15 00` — это 1500.

Обучающие миссии видно сразу. У записи `$02BE3C` все три порога —
`99/99/9999999`, фаза не сдвинется никогда; у `$02C454` наоборот
`1/1/10` — противник проскакивает в старшие фазы с первого хода.

### 5. Цепочки фаз

Шесть длинных слов, которые скрипт кладёт в `a0`, ведут в
`$02894C`–`$028B3C`. Дизассемблер этот кусок долго считал данными: попасть
в эти процедуры можно только через указатель в таблице, а пролога `movem`
у них нет, так что обход по потоку туда не заходил. Сперва я разобрал его
руками и проверил обратной сборкой, потом научил анализатор засевать обход
указателями из таблиц (`make codegaps`) — теперь и цепочки, и скрипты ИИ
миссий, которые их зовут, лежат в `m68k`, и ROM по-прежнему собирается
побайтово.

Восемнадцать цепочек, и все той же формы «правило — `bne` — выход». Из
44 площадок вызова 36 берут одну и ту же таблицу:

| фаза | цепочка | что делает |
|---|---|---|
| 0 | `$02894C` | яйцо вида 1, затем `AiScanUnitsP0` |
| 1 | `$02896C` | яйца видов 1 и 2, затем `AiScanUnitsP1` |
| 2 | `$028994` | яйца шести видов, затем `AiScanUnitsP2` |
| 3 | `$0289F0` | те же шесть яиц, затем `AiScanUnitsP3` |
| 4 | `$028B00` | `AiScanUnitsP45` |
| 5 | `$028B12` | `AiScanUnitsP45` |

Цепочка фазы 2 — единственная с ветвлением, и оно показательно: сперва
`Ai_029962` спрашивает, выбраны ли нормы **редких** видов 3…6, и если
нет, перебор сразу прыгает к ним, минуя массовые виды 1 и 2. А вид 1
пробуется только тогда, когда вида 2 уже набрано по норме. То есть
приоритет — «сначала недобор дорогого».

Остальные шесть таблиц:

| раз | чем отличается |
|---|---|
| 2 | все шесть цепочек только переключают панель — ИИ не делает ничего |
| 2 | в фазе 4 добавлено яйцо вида 5 (`$028A38`) |
| 1 | только яйца, слоя карты нет вовсе |
| 1 | все шесть фаз ведут в одну цепочку `$028B12` |
| 1 | все шесть фаз ведут **прямо** в `AiScanUnitsP2`, без цепочки |
| 1 | в фазах 4 и 5 яйца видов 5 и 4 (`$028A38`, `$028A58`) |

Каждая цепочка заканчивается `move.b #$08/$09/$0C,$F(a4)` — это номер
экрана игрока, а не решение.

### 6. Наконец, порог для команды за 50

Семь процедур `$028B3C`–`$029392` — это и есть искомый слой. Устроены
одинаково: сначала по деньгам противника выбираются три-четыре порога,
потом обходятся его живые юниты, и для каждого сеанс наводится на этого
юнита (`$24`/`$25(a5)` — его клетка), после чего пробуются правила
команды за 50 с этими порогами.

```asm
AiScanUnitsP1:
	move.l	$2(a4),d2               ; деньги второго игрока, BCD
	cmpi.l	#$00000104,d2
	bhi.w	дальше
	move.w	#$0004,d3               ; беден — планка высокая
	move.w	#$0005,d4
	move.w	#$0006,d2
	...
	move.b	$2(a2),d0               ; координаты юнита
	move.b	d0,$24(a5)              ; центр обхода карты
	...
	move.w	d3,d0
	bsr.w	Unit_029E3C             ; правило сравнит свой счёт с d0
```

Рубежи по деньгам — те же круглые BCD-числа, что и в ценах яиц и
растений. Пороги перечислены по возрастанию богатства, по одному на
каждое правило цепочки:

| процедура | рубежи | пороги |
|---|---|---|
| `AiScanUnitsP0` | 104 / 309 / 721 / 1236 | 5·3·4·255 → 4·3·3·9 → 3·2·3·8 → 2·1·2·7 → 1·1·1·6 |
| `AiScanUnitsP1` | 104 / 309 / 721 / 1236 | 6·4·5 → 5·3·4 → 4·2·3 → 3·1·2 → 1·1·1 |
| `AiScanUnitsP2` | 104 / 309 / 721 / 1236 | 6·5·5 → 6·4·5 → 4·3·4 → 3·1·2 → 1·1·1 |
| `AiScanUnitsP3` | 309 / 700 / 1200 / 2000 | 5·255 → 4·3 → 3·2 → 2·1 → 1·1 |
| `AiScanUnitsP45` | 700 / 1200 | 255·2 → 1·1 → 1·1 |

`AiScanUnitsP0` вдобавок смотрит на территорию: при `$22(a5)` от 1 до 7
деньги не спрашиваются вовсе и берутся пороги `1·1·1·255`, при 8…14 —
таблица выше, при 15 и больше процедура не делает ничего.

Читается это просто: **чем богаче противник, тем ниже планка**. С пустым
кошельком правило потребует шесть подходящих клеток вокруг динозавра, с
полным — одну. Значение 255 — «никогда», так что часть правил бедный
противник не пробует вовсе.

Бюджет обхода — `$2(a3)`, слово из подзаписи фазы: сколько юнитов успеть
осмотреть за ход. Он же служит числом шагов курсора в `AiSweepMapCursor`
`$02866A`. А `$2C(a5)` работает как запас сканирований: `Unit_029FE6`
ставит его в `$40`, когда поливка удалась, `UnitLoop_029C8C` и
`UnitLoop_029D64` тратят по единице за обход и молчат, когда дошли до
нуля.

### Что из этого следует

Противник не «думает» — он **растёт по нормативу**. Фаза задаёт, каких
динозавров разводить и как часто оглядываться; кошелёк задаёт,
насколько придирчиво выбирать клетку; территория вокруг гнезда задаёт,
сколько ртов он себе позволит. Все три величины — счётчики, и вся
«стратегия» — таблица из 36 строк по 60 байт.

## Чего я НЕ установил

- Словарь скриптов разобран целиком. `$0239B0` и `$0239E8` — `AiHatchNest1`
  и `AiHatchNest2`, вывод юнита у второго и третьего гнезда; `$02B720` —
  `FindEnemyInWindow`, поиск чужого юнита в окне 6×6 по маске видов и
  набору действий; `$02A194` — `AiGuideUnitAt`, наведение юнита из заданной
  клетки в заданную; `$02A922` — `AiAimAtEnemyNest`, курсор ИИ на первое
  гнездо игрока; `$02B8BC` — `AiPickChain`, выбор цепочки по соотношению
  сил (см. выше); `$009C48` — `EffectDrought`, одна из шести погодных
  процедур банка `$00` ([game-engine.md](game-engine.md)).
- Байт `+$1` подзаписи фазы (`$40`, `$80`, `$C0` у поздних фаз) не читает
  ни одна найденная команда. Похоже на вероятность, которую собирались
  бросать: `AiScanUnitsRand1` и `AiScanUnitsRand2` кубик действительно
  бросают, но сравнивают его с `$1(a6)` — байтом ЗАГОЛОВКА записи, а он
  равен единице во всех 36 записях, так что бросок ничего не решает.
  Называть это ошибкой не берусь.
- Чем наборы B и C отличаются по назначению. Кто их запускает —
  установлено: **скрипты миссий**. Ссылки на `$029AE0`, `$029B1E`,
  `$029B5C`, `$029BD8`, `$029C14` и `$029C50` идут из `$0270xx`–`$0277xx`,
  то есть из тел скриптов, и перед вызовом скрипт кладёт в `d7` маску фаз —
  ровно как для всех прочих правил. Отдельного диспетчера у них нет.
- Чем различаются подготовки `Unit_01E3BE`, `Sub_01E3E6` и `Unit_01E422`
  — по какому набору юнитов каждая ведёт обход.
- `AiPhaseStepAlt` `$0295C4` — полный двойник `AiPhaseStep`, только без
  проверки норм в фазе 1. Площадок вызова у него нет ни одной.
- Чем различаются три варианта землетрясения (`AiQuakeNearEnemies`,
  `…2`, `…3`) — проверкой применимости и анимацией, но почему их три,
  неясно.
- Правила, у которых маски нет, а порог есть, и наоборот: признак у них
  задан как-то иначе.
