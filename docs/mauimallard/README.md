# Разбор Maui Mallard — сводная карта

Второй ROM в этом дереве. Первый — Dyna Brothers 2, его документы лежат
плоско в `docs/game-*.md`, и с этим они не пересекаются.

## Что это за картридж

| поле | значение |
|---|---|
| файл | `platformer.gen`, 3 145 728 байт (3 МиБ) |
| SHA-1 | `87268858DE20721417E050C1097955EEFDBD5298` |
| заголовок | `DONALD STARRING IN MAUI MALLARD` (оба поля, домашнее и зарубежное) |
| издатель, дата | `(C)SEGA 1995.SEP` |
| серийный | `GM MK-1192 -01`, регион `JUE` |
| контрольная сумма | `$5BE5` — **сходится** с пересчётом по `$000200`..конца |
| ОЗУ | `$FF0000-$FFFFFF`, SRAM нет (поле забито пробелами) |

## Как это собирать

Проект разведён с первым ROM целиком: своё имя (`name: mauimallard`), свой
конфиг, свои символы, свой каталог вывода и сборки.

```
make rebuild NAME=mauimallard ROM=platformer.gen CONFIG=platformer.yaml \
     ASM68K=tools/clownassembler_asm68k.exe
```

| что | где |
|---|---|
| конфиг сплита | `platformer.yaml` |
| имена от анализатора | `platformer_symbols.gen.txt` (перезаписывается) |
| **свои имена** | `platformer_symbols.user.txt` (под git, побеждают при склейке) |
| склейка для сборки | `platformer_symbols.txt` (артефакт) |
| дизассемблер | `out/mauimallard/asm/` |
| собранный ROM | `build/mauimallard/mauimallard.bin` |

Питоновские инструменты берут проект из `SEGA2ASM_CONFIG` (Makefile его
экспортирует), пути считает `tools/paths.py`. Инструменты, написанные под
Dyna Brothers (`missions.py`, `maps.py`, `music.py`, `sfx.py`, `aiscript.py`,
`packmap.py`, `dumptext.py`), к этой ROM неприменимы: они читают форматы той
игры. Общие — `analyze.py`, `symbols.py`, `check_split.py`, `findcode.py`,
`vectors.py`, `nameprocs.py`, `rammap.py`, `whocalls.py`, `chains.py`.
`codemap.py` работает, но колонки в нём — адреса ОЗУ Dyna Brothers, то есть
для этой игры бессмысленны.

**Состояние на 2026-09-20: пересборка побайтовая** — `[OK] Побайтово
совпадает с оригиналом`. Это арбитр для любой правки разметки.
Разобрано 115 680 байт кода, 88% окон, а по картриджу в целом
`make coverage` даёт **99,7 %**; неразобранных 9,8 КБ,
и ни одного куска от полутора килобайт.

## Главное, что уже установлено

1. **Код лежит в конце картриджа**, а не в начале: два окна,
   `$28D000-$2AC000` (основное, 126 КБ) и `$2F8BF2-$2F8F9E` (звуковой
   интерфейс). Первые 2,6 МБ — данные.
2. **Код компилировали из C**, а не писали руками. Аргументы кладутся на
   стек (`pea` / `movem.l ...,-(a7)`), вызов — всегда `jsr $XXXXXX.l`
   (1609 из 1687), после вызова стек чистится `lea $N(a7),a7` (402 места).
   Локальные кадры почти всегда без `link` (2 штуки на всю ROM).
3. **Из 64 векторов настоящих три**: сброс, строчное и кадровое прерывания.
   39 векторов — нули, остальные забиты мусором, который даже не попадает в
   ROM. Игра не рассчитывает ни на одно исключение.
4. **Звук отдан Z80**: 68000 только загружает драйвер и кладёт команды в
   кольцевой буфер в ОЗУ Z80 ([sound.md](sound.md)). Сам драйвер разобран:
   169 звуков, 48 восьмибитных сэмплов, DAC по таймеру A с насосом, который
   переписывает сам себя ([z80.md](z80.md)).
5. **Текст хранится обычным ASCII** — не тайлами и не своей кодировкой.
   Меню, пароли и вступление читаются прямо из ROM.
6. **Графика спрайтов не сжата** (графика уровней — сжата, LZSS
   `$29766A`). Тайлы кадров уходят в VRAM прямо из картриджа через
   очередь передач DMA, а разгребает очередь процедура, исполняемая из
   ОЗУ и договаривающаяся со звуковым процессором. Подробности —
   [graphics.md](graphics.md).
7. **Звук разобран до конца и проверен на слух**: `make z80render`
   прогоняет драйвер на эмуляторе и пишет все 27 мелодий в WAV.
