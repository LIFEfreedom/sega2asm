# Звук: драйвер Z80 и команды

Какой звук на какое событие и где какая музыка — спецификация для ремейка
в [sounds.md](sounds.md). Здесь — интерфейс со стороны 68000.

Весь звук отдан Z80. 68000 умеет ровно две вещи: загрузить драйвер в ОЗУ
звукового процессора и положить команду в кольцевой буфер. Формат самих
команд и то, как драйвер их исполняет, **не разбиралось** — здесь только
интерфейс со стороны 68000.

Весь интерфейс лежит отдельным окном кода `$2F8BF2-$2F8F9E`, в самом конце
картриджа, за сэмплами.

## Загрузка драйвера

`$2F8C6C` — загрузчик:

1. `$A11200 = $0100` — снять сброс Z80, `$2F8C4E` — запросить шину и дождаться её;
2. скопировать **`$2ABADA`..`$2AD33B`** (6 241 байт) в `$A00000`;
3. добить нулями до `$A02000` (все 8 КБ ОЗУ Z80);
4. вернуть `sr`.

`$2F8CB2` — импульс сброса: `$A11200 = 0`, пустой цикл на 15 итераций,
`$A11100 = 0` (отдать шину), `$A11200 = $0100`.

`$2F8D7C` — полная инициализация звука; её и зовут при старте из `$297F7A`.
Кроме загрузки и сброса она отправляет драйверу команду `$FF`, команду 11
и **четыре адреса по три байта каждый**:

| аргумент | значение | что это |
|---|---|---|
| 1-й | `$2AD33C` | тембры FM, по 39 байт на запись |
| 2-й | `$2AEB53` | записи по 32 байта, назначение не разобрано |
| 3-й | `$2AECB7` | **звуки: 169 штук**, каждый — набор дорожек |
| 4-й | `$2C785B` | **каталог сэмплов: 48 записей по 12 байт**, дальше данные |

Разбор таблиц со стороны Z80 — в [z80.md](z80.md).

## Кольцевой буфер команд

Команда кладётся в ОЗУ Z80 по адресу `$A01B40`, индекс записи хранится в
`$A00036` и считается по модулю 64 (`andi.b #$3F,d1`). Вокруг записи
обязательны запрос шины и `ori.w #$0700,sr`.

| адрес | роль |
|---|---|
| `$2F8CDE` | пролог: снять адрес возврата, `link a6`, сохранить регистры, запросить шину, прочитать индекс из `$A00036` |
| `$2F8D14` | эпилог: отдать шину, восстановить `sr`, `unlk a6` |
| `$2F8D26` | положить `$FF` (начало команды), затем байт из `d0` |
| `$2F8D32` | положить один байт из `d0`, продвинуть индекс |
| `$2F8D56` | положить три байта (адрес: `d0`, `asr.l #8` — и так трижды) |

## Команды, которые видно со стороны 68000

Аргументы у всех — на стеке (код компилирован из C, см.
[engine.md](engine.md)), поэтому в коде это выглядит как
`pea ($000078).w` + `jsr ($2F8DCC).l` + `lea $4(a7),a7`.

| обёртка | команда | аргументы | сколько вызовов | что это |
|---|---|---|---|---|
| `$2F8DCC` | `$10` | 1 байт | **220** | **начать звук** с этим номером |
| `$2F8DEA` | `$12` | 1 байт | 12 | **остановить звук** с этим номером (`$FF` — все) |
| `$2F8E30` | `$16` | нет | 1 | зовётся только из `$296D1A` |
| `$2F8F60` | `$1B` | 2 длинных слова | 4 | зовётся при PAL с аргументом 1 |
| `$2F8D40` | — | 1 байт | 2 | голая отправка байта, оба вызова — из инициализации `$2F8D7C` |
| `$2F8D56` | — | 3 байта | 4 | голая отправка адреса, все четыре — те самые таблицы из `$2F8D7C` |

Номера команд — это `moveq #N,d0` перед `$2F8D26`, то есть они точные.
Смысл теперь тоже точный: он вычитан из разборщика команд в самом драйвере
(`$090C`, таблица в [z80.md](z80.md)), а не угадан по частоте вызовов.
Музыка и звуковые эффекты — это **одно и то же**: и то и другое запускается
командой `$10` по номеру из одной таблицы на 169 звуков; отличаются они
только числом дорожек (у звука 0 их тринадцать, у большинства эффектов одна).

## Сэмплы

48 штук, все восьмибитные, по 10,6 кГц (45 из 48), 8,9 и 7,6. Каталог — первые `$240`
байт четвёртой таблицы, данные идут сразу за ним: с **`$2C7A9B`** и ровно
до **`$2F8BF2`**, где начинается окно кода звукового интерфейса. Суммарно
200 296 байт. Частота задаётся таймером A микросхемы YM2612, измерена на эмуляторе и
равна `7 670 453 / (144 × делитель)`; подробности и раскладка записи —
в [z80.md](z80.md).
