# Камера и фон: спецификация для ремейка

Всё, что нужно, чтобы камера и фон вели себя как в игре: как камера ищет
цель и догоняет её, где её держат пределы и кто их двигает, как трясёт,
как по каждому из 23 уровней едут полосы фона, что мерцает в палитре и
какие тайлы анимированы. Разбор кода — в [camera.md](camera.md); здесь —
правила и числа.

Числа для движка выгружает `tools/levelspec.py` (он зовёт
`tools/bgspec.py`) в `out/mauimallard/export/`:

| где | что |
|---|---|
| `levels.json`, `rules.camera` | камера: вход, цель, шаг, тряска, пределы и события по уровням |
| `levels.json`, `levels[n].background` | фон уровня: полосы по X и по Y |
| `levels.json`, `levels[n].effects` | анимация палитры и тайлов |
| `levels/levelNN.json`, `background_names` | сама картинка фона (плоскость B), как и прежде |
| `levels/levelNN_tileanim.png` | кадры анимации тайлов: ряд на кадр |

У каждого числа в `levels.sources.json` стоит адрес и текст команды, из
которой оно прочитано; `python tools/bgspec.py --level N` печатает фон
одного уровня.

## 0. Условности

* Карта уровня — плоскость **A**, фон — плоскость **B**; экран 320 × 224.
* Камера `camX`, `camY` — левый верхний угол экрана в мире, **уже с
  тряской** (`$FFFFE1BC`, `$FFFFE1BE`); `t` — счётчик кадров
  (`$FFFFE196`, слово).
* Полоса фона по X задаётся как значение горизонтальной прокрутки VDP:
  `hscroll = k · camX + drift · t (+ волна)`; **плюс сдвигает картинку
  вправо**. У карты `k = −1`, у фона — от 0 (стоит на экране) до −2
  (обгоняет карту вдвое). Экранный X точки полосы = её X в картинке +
  `hscroll`.
* По Y так же, но знак VDP обратный: `vscroll = k · camY + drift · t`,
  **плюс сдвигает картинку вверх**; у карты `k = 1`. Экранный Y = Y в
  картинке − `vscroll`.
* Деление в коде — сдвигом, то есть с округлением вниз; накопители —
  16.16, берётся целая часть.
* Волна: `amp · cos(2π · (phase_f · t + phase_step · i) / 1024)`, i —
  номер строки или столбца внутри полосы; таблица косинуса `$1EAF94`
  (1024 точки, размах `$7FFF`), поэтому размах, например, «7» значит от
  −8 до +7.
* Единицы полос: `row8` — ряд из 8 строк экрана (28 видимых, в таблице
  32), `line` — строка экрана, `column16` — столбец шириной 16 точек (20
  на экран), `whole` — весь экран.

## 1. Камера

### 1.1 Вход на уровень

Камера **ставится сразу**, без подъезда (`$2976B2`):

| что | число | откуда |
|---|---|---|
| X при взгляде вправо | игрок X − **105** | `$2976E4` |
| X при взгляде влево | игрок X − **215** (игрок в 105 от правого края) | `$2976FA` |
| Y | игрок Y − **124** (ноги — в 140 от верха) | `$297726` |
| зажим | 0 … размер уровня − экран (пределы арены здесь не участвуют) | `$297704`, `$29772E` |
| скорость камеры | 0 | `$2976C0` |

### 1.2 Цель

| ось | цель | зажим |
|---|---|---|
| X | игрок X − `off`; при взгляде влево — игрок X − 320 + `off`. `off` = **105**, на уровне 18 — **72** (`$2A6156`) | левый предел … правый − 320, **до** расчёта промаха |
| Y | игрок Y − **124** | **не зажимается**: предел срабатывает только на итоговом положении |

Разворот игрока мгновенно переносит цель на 110 точек (320 − 2 · 105) —
камера переезжает её своим ходом.

### 1.3 Шаг кадра

Обе оси — один алгоритм (`$297748`, `$297870`); `s` — скорость камеры по
оси (`$FF1314`, `$FF1316`), `last` — положение игрока при прошлом замере
(`$FF1318`, `$FF131A`).

```
miss = target - cam
if s == 0 and |miss| <= DEAD:           # DEAD: 12 по X, 4 по Y
    s = 0
elif s != 0 and sign(miss) != sign(s):
    s -= sign(s)                        # тормозим на 1
else:
    d = player - last;  last = player   # замер — только в этой ветке
    if (d xor s) < 0:  d = 0            # при s == 0 это «d < 0 -> 0»
    want = |miss| >> 4
    if axis == X or want > 2:
        want = max(want, |d|)
    a = |s|
    if want != a:  a += 1 if want > a else -1
    s = a * sign(miss)
cam = clamp(cam + s, предел_min, предел_max - экран)
показ = cam + тряска                    # по Y ещё не меньше 0
```

| что | число | откуда |
|---|---|---|
| мёртвая зона по X / по Y (только при `s = 0`) | 12 / 4 | `$2977BA`, `$2978C8` |
| промах делится на | 16 | `$2977FA` |
| разгон и торможение | 1 точка за кадр² | `$29780A`, `$29781C` |
| по Y скорость игрока не учитывается, пока промах/16 не больше | 2 | `$29790A` |
| по Y шаг пропускается целиком, если игрок выше 0 или ниже `нижний предел − 16` | 16 | `$29789E` |

Три следствия для ремейка:

* Скорость игрока — **нижняя граница** желаемой скорости, а не потолок:
  при большом промахе камера едет быстрее игрока (промах/16).
* Замер `last` обновляется только в ветке «догоняем», поэтому после
  остановки `d` — это весь путь игрока с прошлого замера, а не за кадр.
  При `s = 0` сдвиг влево обнуляется, вправо — нет.
* По Y цель не зажата: у верхнего и нижнего предела скорость продолжает
  расти, пока камера упирается, и после разворота игрока ей сперва нужно
  затормозить.

Когда игрок падает за нижний край (Y ≥ нижний предел − 16), вертикаль
замирает вовсе, даже тряска не прибавляется.

### 1.4 Пределы и кто их двигает

При входе: левый и верхний — 0, правый и нижний — размер уровня
(`$29866A`). Игрок ниже нижнего предела — гибель (`$2A4EA6`).

| уровень | кто | что делает |
|---|---|---|
| 2 | `$29E4FC` (`camera_limit`) | игрок поднялся выше объекта — нижний предел `$200`, дальше −8 за кадр до `$F0`: пол арены шамана поднимается |
| 5 | `$29C018` (`camera_limit`) | игрок X ≥ 3056 — левый предел = камера X − 32, дальше +2 за кадр до 2992 (`$0BB0`); дорога назад закрыта |
| 9 | `$29E55E` (`camera_limit`) | игрок в полосе высот у объекта — **нижний** предел `$E0` (камера Y прижата к 0); дошёл до X ≤ `$1F0` — по X от `$20` до `$230`, музыка `$54`, генераторы арены |
| 13 | зона воды `$2A06FA` | игрок X ≥ `$0CE0` — вода опускается на `$30`, левый предел = камера X, дальше +2 за кадр до `$0CA0` |
| 17 | фон `$2A5B9E` | когда идол взвёл `$FF2150`: нижний предел −1 раз в 4 кадра до `$F0` — арена сжимается |

(В [camera.md](camera.md) замок уровня 9 записан как «`$FF1A90 = $E0`»:
длинная запись `move.l #$000000E0,($FF1A90)` кладёт 0 в верхний предел и
`$E0` — в **нижний**.)

### 1.5 Тряска и качка

Тряска — только по Y: `$FF131E` прибавляется к камере на один кадр и
гасится. Рисунок: в кадрах `t % 4 == 2` — вверх на размах, в остальных — 0.

| источник | вид | размах |
|---|---|---|
| уровень 3: сломан четвёртый объект кода 164 (`quake_trigger`, `$29BDCC`) | постоянная (`$2995D0`) | три фазы (`$2993FE`): 320 кадров — 7 − `$FF214C`/64, растёт от 2 до 7; потом восемь шагов раз в 4 кадра, когда камера и объекты сдвигаются на 16 вверх; потом 144 кадра — `$FF214C`/16, от 9 к 0. Всё это время вертикаль камеры стоит, звук `$9B` |
| уровень 17: идол всплывает (`$2A2D84`) | постоянная | 2 |
| `$29B4C8`: тяжёлый объект приземлился (звук `$0B`) | затухающая (`$2926DC`): −1 за толчок | 4 |
| `$2A66EC`: три предмета над игроком (x, x ± 64) | затухающая | 6 |

**Качка** уровней 14 и 15 — тот же `$FF131E`, но из косинуса, каждый кадр:
`amp · cos(2π · t / 128)`, `amp` = 7 на уровне 14 и 15 на уровне 15
(`$2A5B02`, `$2A5ADC`). Качается вся картинка — карта, объекты и фон.

**Заморозка:** `$FF1326` останавливает горизонталь (выброс игрока
`$2A2530`), `$FF1327` — вертикаль (землетрясение уровня 3). Режимы
«игрок в центре» (`$FF1320`) и «вертикаль к низу арены» (`$FF1324`) в
игре мертвы: их гасят при входе и нигде не взводят.

## 2. Фон по уровням

Плоскость B — одна картинка (`background_names`, 64 × 32 клетки по 8
точек, 512 × 256; по краям она заворачивается). Полосы режут её по строкам экрана или по столбцам. Плоскость
B по вертикали в режимах «весь экран» **не движется**: за кадр пишут только
слово плоскости A (`$2A55B2`); исключение — уровни 16 и 17.

| уровни | процедура | X | Y | эффекты |
|---|---|---|---|---|
| 0-2 | `$2A59B0` | ряды: ½ камеры, верхние три полосы плывут влево | стоит | 2: тайлы |
| 3-5 | `$2A5972` | ряды: верх плывёт вправо без камеры, низ — «пол» | стоит | тайлы; вспышка раз в 540 кадров; 3: волна красного по метке |
| 6 | `$2A5BD4` | весь фон ½ камеры | стоит | палитра |
| 7-9 | `$2A59B6` | пять полос: ¼, ¼ с дрейфом, ½, ¾ | стоит | 7, 9: тайлы |
| 10 | `$2A5A0C` | стоит | столбцы: волна ±8 и сползание вниз | (палитра задана, не играет) |
| 11 | `$2A5A5E` | стоит | столбцы: пять глубин, фон падает всё быстрее | (палитра задана, не играет) |
| 12-13 | `$2A59C6` | стоит | столбцы: чаша | палитра; 13: тайлы |
| 14 | `$2A5B02` | четыре полосы ⅛…½ | стоит | качка ±7 |
| 15 | `$2A5ADC` | ½ камеры, полосы плывут вправо 1-4 | стоит | качка ±15 |
| 16 | `$2A5B94` | небо 1/128 с волной, передний край 2× | низ до 32 | тайлы |
| 17 | `$2A5B9E` | небо 1/128, передний край 2× | низ до 32 | тайлы; сжатие арены |
| 18 | `$2A5BCA` | строки через одну: 8 и 4 в кадр | стоит | — |
| 19-22 | `$2A59BC` | 17 полос неба плывут вправо, низ ¼ | стоит | — |

Ниже `k` — доля камеры в `hscroll`/`vscroll` (раздел 0), дрейф — в
точках за кадр (для X: плюс — картинка едет вправо; для Y: плюс —
вверх).

**Уровни 0-2** (ряды по 8 строк, `$2A5C56`):

| ряды | k | дрейф |
|---|---|---|
| 0-7 | −½ | −0,5 |
| 8-10 | −½ | −0,25 |
| 11-13 | −½ | −0,125 |
| 14-31 | −½ | 0 |

Облака плывут влево сами, по накопителям `$FF2060` (+`$8000`, `$4000`,
`$2000` в 16.16). Четвёртый накопитель (+`$1000`) считается, но не
читается.

**Уровни 3-5** (`$2A5C1C`): ряды 0-19 — `k = 0`, дрейф +0,25 (t >> 2);
ряд 20 — +0,125; ряд 21 — +0,0625; ряды 22-31 — «пол»: `k = −j/8`, j = 0…9
по ряду сверху вниз (видимые 22-27 — от 0 до −⅝). Раз в **540 кадров**
(`$2A5972`) один раз проигрывается вспышка `$2887F4` (раздел 3).

**Уровень 6** (`$2A5520`): все ряды `k = −½`, дрейфа нет.

**Уровни 7-9** (`$2A5CCC`):

| ряды | k | дрейф |
|---|---|---|
| 0-3 | −¼ | −0,5 |
| 4-8 | −¼ | −0,25 |
| 9-15 | −¼ | 0 |
| 16-20 | −½ | 0 |
| 21-27 | −¾ | 0 |

**Уровень 10** (`$2A5A0C`): по X фон стоит (`$2A552C`). По Y — 20
столбцов, `vscroll = −⌊t/2⌋ + 7 · cos(2π · (8t + 178 · i)/1024)`: вся
картинка сползает вниз на полточки за кадр, а столбцы колышутся с
периодом 128 кадров и сдвигом фазы 178/1024 между соседними. Камера в
формуле не участвует.

**Уровень 11** (`$2A5A5E`): по X стоит. По Y `v = camY − t · 2^(s+1)`,
где ступень s — `$FF2150`: 0 на входе, 1, 2 и 3 ставят метки `$2A169A`,
`$2A16A4`, `$2A16AE`. Столбцы получают долю от `v`:

| столбцы | доля |
|---|---|
| 0, 1, 18, 19 | 1 |
| 2, 3, 16, 17 | ¾ |
| 4, 5, 14, 15 | ½ |
| 6, 7, 12, 13 | ¼ |
| 8-11 | ⅛ |

То есть края едут вместе с картой, середина — в восемь раз медленнее, а
сверх камеры всё падает вниз со скоростью 2, 4, 8, 16 точек за кадр
(умноженной на долю) — чем выше игрок забрался, тем быстрее.

**Уровни 12-13** (`$2A59C6`): по X стоит. По Y: столбцы 0-2 и 17-19 —
`k = 1` (едут с картой), 3-5 и 14-16 — `k = ½`, середина 6-13 стоит
(`$FF20E0` обнуляют при входе, `$29863A`).

**Уровень 14** (`$2A5DFE`): ряды 0-13 — `k = −⅛`, 14-15 — −¼, 16-19 —
−⅜, 20-25 — −½; ряды 26-31 не пишутся (остаются нулём после сброса
`$28FABC`). Плюс качка ±7 (1.5).

**Уровень 15** (`$2A5E44`): все ряды `k = −½`; дрейф вправо: ряды 0-13 —
+1, 14-15 — +2, 16-19 — +3, 20-25 — +4; ряды 26-31 не пишутся. Плюс
качка ±15.

**Уровень 16** (построчно, `$2A624A`; по Y `$2A6218`):

* плоскость B по Y: `vscroll = clamp(camY − (нижний предел − 256), 0, 32)` —
  у самого дна фон поднимается до 32 точек;
* небо: `k = −1/128`; сверху `max(0, 223 − camY)` строк, пока
  `camX ≤ $500`, ещё и волна ±3 (фаза 4 за кадр, 12 на строку, период
  256 кадров);
* передний край — последние 32 строки списка, на экране их столько снизу,
  на сколько поднята плоскость B: `k = −2` (быстрее карты вдвое) и волна
  ±7 с той же фазой.

**Уровень 17** (`$2A62F6`): то же без волны неба; сжатие арены — 1.4.

**Уровень 18** (`$2A636E`): чётные строки — `k = −⅛`, дрейф +8; нечётные —
`k = −¼`, дрейф +4. Две картинки вперемешку через строку.

**Уровни 19-22** (построчно, `$2A5D26`):

| строки | k | дрейф вправо |
|---|---|---|
| 0-63 | 0 | 16 полос по 4 строки: 3,000; 2,625; 2,297; 2,010; 1,759; 1,539; 1,346; 1,178; 1,031; 0,902; 0,789; **0,656**; 0,691; 0,604; 0,529; 0,463 |
| 64-75 | 0 | 0 |
| 76-79 | 0 | 0,405 |
| 80-105 | 0 | 0 |
| 106-223 | −¼ | 0 |

Ряд скоростей — 3 · (7/8)^n, кроме двенадцатой полосы: `$A800` вставлен
руками и медленнее соседней снизу ([camera.md](camera.md)). Процедура
пишет 225 строк — одну лишнюю за концом таблицы `$FF1C60`.

## 3. Палитра и анимированные тайлы

**Анимация палитры** — таблица поля `+$1C` уровня. Формат:
[engine.md](engine.md); в JSON — индекс CRAM (0-63), сколько кадров
держится каждый цвет и сами цвета в формате CRAM `0BGR` (по три бита:
`$00E` — красный, `$0E0` — зелёный, `$E00` — синий). Шаг делает `$2A57CA`, а его
зовут **только** построители фона уровней 3-6, 12, 13 и 16-22. Поэтому:

| уровни | таблица | что |
|---|---|---|
| 6 | `$288C86` | индекс 31: пульс красного `000`…`00A`…`002`, 10 цветов по 11 кадров |
| 12, 13 | `$288BF2` | индексы 24-31: мерцание белого `EEE` и бледно-зелёного `CEC` со сдвигом фазы, по 4 кадра (24-27) и по 3 (28-31) |
| 10, 11 | `$288C64` | **задана, но не играет**: построители `$2A5A0C` и `$2A5A5E` шаг не зовут (а была бы — красно-оранжевое `00A`-`26E` на индексах 12 и 13) |
| 3 | `$288A8A` | не из записи, а по метке `$29BFE0`: индексы 17-23, бегущая волна **синего** `200`…`E00`, по 2 кадра на цвет; `$29BFFC` выключает |
| 3-5 | `$2887F4` | вспышка раз в 540 кадров: индексы 1, 3-9, 12, 14 мигают 30 раз по 2 кадра, **один проход** (`$2A58EE`) |

**Анимация тайлов** — таблица поля `+$18`, записей `+$3A`
([engine.md](engine.md)). Кадр — кусок из ROM, который копируется
поверх первых тайлов набора уровня; первый кадр совпадает с тайлами
набора, то есть в покое карта уже нарисована кадром 0.

| уровни | тайлов | кадров | кадр держится |
|---|---|---|---|
| 2 | 8 | 4 | 16 кадров |
| 3-5 | 26 | 8 | 7 |
| 7, 9 | 12 | 6 | 8 |
| 13 | 49 | 3 | 6 |
| 16, 17 | 5 | 3 | 5 |

Пиксели кадров — `levels/levelNN_tileanim.png` (ряд на кадр, серая шкала
по номеру цвета, как `levelNN_tiles.png`).

## 4. Поправки к прежним документам

* [camera.md](camera.md): «потолок — скорость утки» — наоборот, скорость
  игрока — нижняя граница желаемой скорости (1.3); по Y цель не
  зажимается; замок уровня 9 ставит нижний предел, а не верхний.
* [engine.md](engine.md): «уровни 6, 10, 11, 12 и 13 действительно
  мерцают» — мерцают 6, 12 и 13 (и 3 по метке); на 10 и 11 таблица есть,
  а шага нет. Там же волна `$288A8A` названа красной — цвета `200`…`E00`
  в CRAM синие.
* `tools/scroll.py`: у `$2A5BD4` (уровень 6) не «анимация тайлов», а
  анимация палитры; фон едет вполовину камеры.
* [levels.md](levels.md): таймер `$FF214A` заводит землетрясение уровня 3
  (1.5); `$29E55E` на уровне 9 — не генератор, а замок арены.
