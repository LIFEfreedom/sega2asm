# Окна в банке кода: что там на самом деле

Внутри `$28D000`-`$2AC000` дизассемблер оставил **130 кусков, 10 600 байт**,
размеченных как данные. Это не значит, что там данные: обход идёт по потоку
управления, и всё, до чего добираются через таблицу или куда сваливаются с
середины, он не находит. Сегодня это уже дважды стоило ручного разбора —
таблица опкодов `$2A64AE` и `data_125` внутри обработчика противника.

Разбирает `tools/gaps.py`:

```
python tools/gaps.py            сводка по видам
python tools/gaps.py --list     окно за окном, с доказательством
python tools/gaps.py --code     только те, что похожи на код
python tools/gaps.py --show data_111
```

## Признак — улика, а не плотность

`findcode.py` считает плотность редких опкодов. Здесь наоборот: каждая
улика проверяема глазами.

| улика | что значит |
|---|---|
| таблица `bra.w` | все слова через четыре байта равны `$6000` |
| таблица указателей | подряд идут длинные слова из банка кода |
| вход снаружи | команда ветвится или зовёт адрес ВНУТРИ окна |
| цель таблицы `bra.w` | окно — цель такой таблицы из другого окна |
| ставится процедурой | `move.l #adr,...` с адресом внутри окна |
| указатель в ПЗУ | длинное слово где угодно в ПЗУ равно адресу внутри |
| проваливание | команда прямо перед окном не `rts` и не `bra` |

Важно, ГДЕ вход. Вход ровно в начало окна — это найденная процедура;
вход в середину двухкилобайтного куска — скорее совпадение, поэтому виды
разделены.

**Сначала улик было три** (вход снаружи, таблицы, проваливание), и признак
дал 34 байта кода из 10 600 — то есть промахнулся мимо обоих кусков,
которые я в тот же день разбирал руками. Причина в том, что входят в них
не командой: в `data_111` ведёт таблица `bra.w`, а в `data_125` — длинное
слово из среза состояний. После добавления указателей счёт стал такой:

| вид | окон | байт |
|---|---|---|
| данные | 111 | 6586 |
| код (вход в середину) | 3 | 3374 |
| **код (вход в начало)** | **6** | **360** |
| таблица `bra.w` | 2 | 132 |
| таблица указателей | 2 | 126 |
| код (проваливание) | 6 | 22 |

Две трети окон — действительно данные. «Вход в середину» — это `data_01`
(1170 байт в начале банка) и `data_135` (1990 байт в конце): у каждого по
одному-два указателя куда-то внутрь, чего мало для вывода.

**`data_135` с тех пор опознан.** Единственный указатель в него шёл из
`$2F8C84`, а это оказался копировщик драйвера Z80:

```asm
loc_2F8C6C:
	move.w	#$0100,(Z80_RESET).l
	jsr	(loc_2F8C4E).l      ; забрать шину
	lea	($2ABADA).l,a0      ; ОБРАЗ ДРАЙВЕРА
	lea	($2AD33B).l,a1      ; и его конец
```

То есть `data_135` — начало образа драйвера Z80, `$2ABADA`-`$2AD33B`, и
данные это по построению. Заодно видно, что образ вылезает за конец банка
обработчиков.

## Шесть окон со входом в начало

Разобраны по одному; из шести кодом оказалось одно.

### `data_42`, `$2972EE`, 46 байт — КОД

Цель таблицы `bra.w`, вход ровно в начало. Это продолжение обработчиков
команд скрипта анимации: соседний кусок `$297126`-`$2972EE` уже переведён
в код руками, а этот остался.

```
$2972EE  30 19        move.w (a1)+,d0
$2972F0  20 19        move.l (a1)+,d0
$2972F2  08 10 00 09  btst #9,(a0)
$2972F6  66 36        bne.s +$36
$2972F8  61 00 17 56  bsr.w ...
```

### `data_74`, `$29D39C`, 32 байта — ВЕЕР ЗАЛПА

Не код, а две таблицы встык, и потребитель разбирает их без остатка:

```asm
	lea	(data_74).l,a2
	move.w	$4C(a0),d0           ; фаза
	move.b	($1,a2,d0.w),d1      ; порядок
	lsl.w	#2,d1
	lea	($29D3A8).l,a3
	move.l	($0,a3,d1.w),$16(a1) ; СКОРОСТЬ длинным словом
	addq.w	#1,d0
	cmp.b	(a2),d0
	blt.s	loc_29D4A0
	moveq	#0,d0                ; заворот
	...
	move.w	#$003C,$6(a0)        ; следующий выстрел через 60 кадров
```

Первый байт — длина цикла, `$0A`. Дальше десять номеров, это **порядок**:
`0 1 4 2 3 0 4 1 3 2`. С `$29D3A8` идут пять скоростей длинными словами:

| № | по горизонтали | по вертикали |
|---|---|---|
| 0 | −`$180` | −`$400` |
| 1 | −`$100` | −`$500` |
| 2 | 0 | −`$600` |
| 3 | +`$100` | −`$500` |
| 4 | +`$180` | −`$400` |

Симметричный веер из пяти направлений вверх, и стреляют им не по кругу, а
вразнобой по зашитому списку из десяти шагов.

### `data_124`, `$2A8B1C`, 24 байта — ВСПЫШКА ОТ ПОПАДАНИЯ

Две записи по 12 байт, и обе уходят в `loc_2A5830`, а та ставит
обработчик кадра, который шлёт кусок палитры в CRAM (`$2A586C`:
`ori.w #$C000,d2` — команда записи CRAM):

```
$2A8B1C  00 35 00 04  0E EE 0E EE 0E EE 0E EE   индекс $35, 4 цвета: белый
$2A8B28  00 35 00 04  00 0A 00 4E 00 8E 04 EE   он же, свои цвета
```

Ставит их маленький автомат, который держит следующий шаг в `-$4(a0)` и
считает `$FF2228`: сперва белый, через несколько кадров обратно. То есть
**побелеть от удара и вернуться**.

### `data_26`, `$294F24`, 12 байт — ТРИ СКРИПТА

`00 1D 8F 08 | 00 1D 8F 14 | 00 1D 8F 20` — три длинных слова в окно
скриптов анимации `$1D6E38`-`$1DB670`. Таблица скриптов, берут из
`$29507C`. Классификатор принял её за код только потому, что не проверяет
указатели В ДРУГИЕ окна, кроме банка кода.

### `data_52`, `$2990FC`, 36 байт — ДЕВЯТЬ НАБОРОВ

Девять записей по четыре байта, первый байт — сколько дальше значимых:

```
01 00 00 00      02 01 02 00      02 02 03 00
01 01 00 00      01 03 00 00      03 01 02 03
01 02 00 00      02 01 03 00      01 04 00 00
```

Счётчик и до трёх номеров, номера в пределах 1..4. Чего именно — не
установлено; берут из `$29912E`, сразу за окном начинается код.

### `data_111`, `$2A64F4`, 210 байт — КОД

Обработчики четырнадцати команд программы поведения `+$48`. Разобраны
целиком, таблица команд в [engine.md](engine.md).

## Что это меняет

Из 10 600 байт «данных» в банке кода **настоящего непереведённого кода —
256 байт** (`data_42` и `data_111`), и `data_111` уже разобран вручную.
Остальное — таблицы и данные, лежащие внутри кодового банка потому, что
их читают соседние процедуры.

То есть пункт «в банке не разобрано 15 КБ» надо понимать не как «потерян
код», а как «внутри кода много мелких таблиц». Кода потеряно мало, и он
теперь назван поимённо.

**Проверять переводом.** Правильный способ закрепить находку — поменять в
`platformer.yaml` `type: bin` на `type: m68k`, убрать `subdir` и собрать:
побайтовая сверка и есть доказательство. Здесь этого не делалось —
`platformer.yaml` правит соседняя сессия.
