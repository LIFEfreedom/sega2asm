# Драйвер Z80

Образ лежит в ROM по `$2ABADA`, длиной `$1862` байта, и грузится в ОЗУ
звукового процессора с нулевого адреса как есть — без сжатия
(загрузчик `$2F8C6C` со стороны 68000, см. [sound.md](sound.md)).

Листинг:

```bash
make z80dis Z80ROM=2ABADA:1862 Z80LEN=1862 NAME=mauimallard ROM=platformer.gen CONFIG=platformer.yaml
```

## Карта ОЗУ Z80

| адрес | что |
|---|---|
| `$0000-$1861` | загруженный образ: код и данные |
| `$0036` | индекс записи в кольце — его ведёт **68000** |
| `$0037` | индекс чтения — его ведёт драйвер |
| `$003E-$003F` | сюда прерывание кладёт `sp`; старший байт служит признаком тика |
| `$0040` | счётчик необработанных тиков |
| `$0A6C-$0A77` | четыре адреса в ROM по три байта, присланные 68000 |
| `$1861-$1AD0` | по 39 байт на слот: **копия текущего тембра** (`$0462`) |
| `$1B20` | вершина стека; здесь же флаги рукопожатия с 68000 |
| `$1B22…` | маленький массив параметров (команда `$1B` пишет сюда) |
| `$1B40-$1B7F` | кольцо команд, 64 байта |
| `$1B80-$1D7F` | **16 слотов по 32 байта** — играющие дорожки |
| `$1D80-$1E7F` | по 16 байт на слот: **кэш куска скрипта** |

## Почтовый ящик

68000 кладёт в кольцо `$1B40` байты и двигает индекс `$0036`; драйвер
сравнивает его со своим `$0037` и разбирает всё, что появилось. Читатель
(`$01D1`) — цикл ожидания, и **внутри него драйвер продолжает гонять DAC**,
иначе звук бы заикался на каждой команде.

Команда всегда начинается с байта `$FF` (`$091A` проверяет именно его),
дальше идёт номер команды, дальше — её аргументы.

| код | адрес | что делает |
|---|---|---|
| `$00` | `$099D` | слот + байт: чтение через `$112A`/`$11DF` |
| `$01` | `$09B1` | два байта → `$1677` |
| `$02` | `$09BF` | без аргументов → `$1701` |
| `$03` | `$09C5` | байт → `$1741` (чтение патча из таблицы 1) |
| `$04` | `$09CE` | байт → `$0F2F` |
| `$05` | `$0A12` | байт → `$0DF4` |
| `$06` | `$0A1B` | слот + байт → поле `+$1D` слота |
| `$07` | `$0A34` | слот + байт → бит 6 поля `+$6` |
| **`$0B`** | `$0A5D` | **12 байт → `$0A6C`: четыре адреса таблиц** |
| `$0C` | `$0A78` | снять бит 4 во всех слотах |
| `$0D` | `$0B50` | взвести бит 4 во всех играющих слотах |
| `$0E` | `$0A96` | слот + байт → бит 7 поля `+$6` |
| **`$10`** | `$0A4B` | **начать звук с номером** (220 вызовов из игры) |
| **`$12`** | `$0A54` | **остановить звук с номером**, `$FF` — все |
| `$14` | `$0AAD` | слот + байт → поле `+$1C` |
| **`$16`** | `$0AB9` | **остановить всё** |
| `$17` | `$0AD9` | три байта: найти слот по `+$E`/`+$F`, бит 1 поля `+$6` |
| `$1A` | `$0B16` | два байта, правка записи через `$112A` |
| **`$1B`** | `$0B2B` | **индекс + значение → `$1B22+индекс`** (игра шлёт `$15`←1 на PAL) |
| `$1C` | `$0B3C` | слот → взвести бит 5 поля `+$6` |
| `$1D` | `$0B46` | слот → снять бит 5 |
| `$1E` | `$09D7` | два байта: найти слот по `+$E`/`+$F` → `$0F2F` |
| `$1F` | `$0B6F` | слот + байт → поле `+$1E` |
| `$20` | `$0B7B` | байт → `$15A8` |

Игра пользуется пятью: `$0B` при инициализации, `$10`, `$12`, `$16` и
`$1B`. Остальные шестнадцать в ROM 68000 не зовёт никто — драйвер умеет
больше, чем игре понадобилось.

## Четыре таблицы

Адреса присылает 68000 командой `$0B`, по три байта, младшим байтом вперёд.

| № | адрес | размер записи | что |
|---|---|---|---|
| 1 | `$2AD33C` | **39 байт** | тембры FM: индекс — поле `+$D` слота, через таблицу слов-смещений (`$1719`) |
| 2 | `$2AEB53` | **32 байта** | ещё один набор записей по индексу (`$0E46`) |
| 3 | `$2AECB7` | переменный | **звуки: 169 штук** |
| 4 | `$2C785B` | **12 байт** | **каталог сэмплов: 48 штук** |

Все четыре одинаково устроены снаружи: слово-смещение по индексу, потом
запись по этому смещению; и смещения, и адреса внутри — **от начала самой
таблицы**, а не от начала ROM.

### Звук — это набор дорожек

По номеру звука берётся слово из `$2AECB7 + n*2`, по нему — описатель:

```
+$0        сколько дорожек (1..16)
+$1 …      по три байта на дорожку: смещение скрипта от начала таблицы
```

Драйвер читает описатель с запасом, `$31` = 49 байт — ровно
`1 + 16*3`. Дальше он занимает столько слотов, сколько дорожек. Свободным
считается слот, у которого в `+$6` не взведены биты 0 и 5.

Раскладка слота, насколько она разобрана:

| поле | что |
|---|---|
| `+$0..+$2` | адрес куска скрипта, лежащего в кэше (`$FFFFFF` — кэш пуст) |
| `+$3..+$5` | текущая позиция в скрипте, 24 бита |
| `+$6` | состояние: бит 0 занят, бит 1 заглушен, бит 3 второй темп, бит 4 играет, бит 5 приостановлен |
| `+$7..+$8` | счётчик до следующего события; считает **вверх** до нуля, `$FFFF` — сработать сразу |
| `+$9..+$A` | шаг, взятый из потока (`$C0`-числа) |
| `+$B..+$C` | время звучания ноты (`$80`-числа) |
| `+$D` | номер тембра |
| `+$E` | номер звука, `+$F` — номер дорожки |
| `+$10..+$1B` | стек циклов: четыре записи по три байта |
| `+$1C` | громкость канала (команда `$6A`) |
| `+$1E` | громкость дорожки (`$72 05`), складывается с общей `$15A8` |

Скрипт читается не байт за байтом из ROM, а кусками по 16 байт в кэш
(`$03F2`): окно Z80 в картридж переключается банковым регистром, и дёргать
его на каждый байт было бы слишком дорого.

Проверяется на данных: первое смещение в таблице — `$0152`, то есть записей
`$152/2` = **169**; у звука 0 тринадцать дорожек и его описатель занимает
`1 + 13*3 = 40` байт, ровно до описателя звука 1.

### Сэмплы

Каталог — 48 записей по 12 байт, сразу за ними идут сами данные:

| поле | что |
|---|---|
| `+$0` | флаги: **бит 7 — упаковка по 4 бита**, младший ниббл — делитель скорости |
| `+$1..+$3` | смещение данных от начала таблицы (24 бита) |
| `+$4..+$5` | добавочное смещение |
| `+$6..+$7` | длина |

Данные начинаются на `+$240` — ровно там, где кончается каталог, — то есть
с `$2C7A9B`, а последний сэмпл кончается на **`$2F8BF2`**: там же начинается
окно кода звукового интерфейса 68000. Суммарно 200 296 байт.

Нота выбирает сэмпл как `нота - $30` (с заворотом `+$60`), то есть ноты
`$30`..`$5F` — это сэмплы 0..47.

**Все 48 записей в этой игре восьмибитные**: бит 7 не взведён ни у одной.
Путь для четырёхбитных данных в драйвере есть и работает, но игра им не
пользуется.

Делитель задаёт частоту через таймер A микросхемы YM2612: драйвер пишет
`-(делитель)` в регистры `$24`/`$25`, что даёт период таймера ровно в
`делитель` тиков, то есть

> частота = 7 670 453 / (72 × делитель)

Делитель 5 — это 21,3 кГц (так у большинства сэмплов), 7 — 15,2 кГц.

## Скрипт дорожки

Дорожка — это поток байт, который драйвер разбирает в `$04B4`/`$050E`.
Разбор повторён инструментом:

```bash
make z80seq                 # сводка по всем 169 звукам
make z80seq SOUND=0         # звук целиком, дорожка за дорожкой
make z80seq SOUND=0 TRACK=2
```

**Проверка грамматики:** все **363 дорожки** всех 169 звуков разбираются до
команды «конец дорожки» и ни одна не обрывается на неизвестном байте.
Средняя длина 274 байта, самая длинная 4 038.

### Как читается байт

| байт | что |
|---|---|
| `$00..$5F` | **нота**. Что значит номер — решает тип текущего тембра: у ударных это сэмпл `нота-$30`, у FM и PSG высота |
| `$60..$72` | команда, у каждой своё число аргументов |
| `$73..$7F` | драйвер молча пропускает |
| `$80..$BF` | **время звучания** ноты: шесть бит на байт |
| `$C0..$FF` | **шаг** до следующего события: шесть бит на байт |

Числа набираются подряд идущими байтами с тем же двубитным признаком
(`$04E6`): `C1 E0` — это `(1<<6)|$20` = 96. Внутри драйвера они хранятся со
знаком минус, потому что счётчик `+$7/+$8` слота считает вверх до нуля.

Нота не выдаётся сразу: сперва пишется в канал, а дорожка засыпает на
текущий шаг. Шаг 0 означает «следующее событие в тот же тик», и именно так
набираются аккорды и цепочки команд.

### Команды

| код | аргументы | что делает |
|---|---|---|
| `$60` | — | **конец дорожки**: слот освобождается |
| `$61` | тембр | взять запись из таблицы тембров |
| `$62` | номер | взять запись из таблицы 2 |
| `$63` | — | **пауза** на текущий шаг |
| `$64` | сколько | **начало цикла**; `$7F` — бесконечно |
| `$65` | — | **конец цикла** |
| `$66` | 0/1 | бит 6 состояния слота |
| `$67` | 0/1 | бит 7 состояния слота |
| `$68` | значение | **темп**: `(значение+$28)` масштабируется и ложится в `$0885` — шаг, который тик прибавляет к счётчику (`$0041`) |
| `$69` | дорожка | заглушить или включить (бит 4) **другую дорожку того же звука** |
| `$6A` | громкость | громкость канала (поле `+$1C`) |
| `$6B` | номер | **запустить другой звук** |
| `$6C` | два байта | пара в область `$0F4F` |
| `$6D` | — | перевести дорожку на **второй темп** |
| `$6E` | значение | правка поля текущего тембра (только для ударных) |
| `$6F` | смещение 16 бит | **переход** вперёд или назад |
| `$70` | индекс, значение | **параметр** `$1B22+индекс` := значение |
| `$71` | индекс, режим, значение, смещение | **условный переход**: сравнить значение с параметром |
| `$72` | подкоманда, значение | см. ниже |

Режимы сравнения: 1 — равно, 2 — больше или равно, 3 — больше, 4 — меньше
или равно, 5 — меньше, всё остальное (включая 0) — не равно. Переход всегда
вперёд, на один байт смещения.

Подкоманды `$72`: 0 — остановить звук, 1 — приглушить звук, 2 — продолжить
все, 3 — приглушить звук, номер которого лежит в параметре 0, 4 — общая
громкость (`$15A8`), **5 — громкость этой дорожки** (поле `+$1E`; её
`$11DF` складывает с общей).

### Что из этого игра использует

На 31 077 нот приходится:

| команда | раз |
|---|---|
| `$72` (почти всегда подкоманда 5 — громкость дорожки) | 7 213 |
| `$61` тембр | 1 099 |
| `$6A` громкость канала | 411 |
| `$6D` второй темп | 141 |
| `$63` пауза | 120 |
| `$6B` запуск другого звука | 66 |
| `$66` | 57 |
| `$64`/`$65` циклы | 46 + 46 |
| `$71` условие / `$70` параметр | 41 + 38 |
| `$68`, `$62`, `$6F`, `$6C`, `$6E` | 34, 39, 26, 27, 5 |

Параметры и условные переходы — не украшение. Звук 1 начинается с
`если $01 != параметр[$00] → играть`, а перед первой нотой ставит
`параметр[$00] := $01` и обнуляет его в конце: защита от повторного запуска
того же звука, написанная **в самих данных**, а не в коде.

А первая дорожка звука 0 открывается так:

```
68 50            темп $50
71 15 00 01 03   если $01 != параметр[$15] -> дальше
68 68            темп $68
```

Параметр `$15` — тот самый, в который 68000 кладёт единицу, обнаружив PAL
(команда `$1B`). То есть **музыка сама подстраивает темп под пятьдесят
герц**, читая параметр, выставленный другим процессором.

### Тембры

Первый байт записи тембра решает, чем играется нота:

| тип | чем | сколько тембров |
|---|---|---|
| 0 | **FM** (YM2612) | 149 |
| 1 | **ударные**: нота выбирает сэмпл `нота-$30` | 1 |
| 2 | PSG | 2 |
| 3 | PSG, другой набор каналов | 4 |

Всего в таблице 156 тембров. Единственный ударный тембр — `$0F`, и именно
он стоит в барабанных дорожках.

## Запись тембра

39 байт на запись, 156 записей. Раскладка снята не на глаз: в драйвере
лежит таблица `$15F5` из пар «регистр YM2612, смещение в записи», и
процедура `$15A9` по ней заливает тембр в микросхему. Поле с взведённым
битом 7 (`40 85`) — уровень несущей: он не пишется как есть, а
масштабируется громкостью ноты, а какие операторы несущие, решает таблица
`$159F` по алгоритму.

```bash
make z80voice            # сводка по всем 156
make z80voice VOICE=0    # один тембр по-человечески
```

| байт | что |
|---|---|
| `+0` | **тип**: 0 FM, 1 ударные, 2 и 3 PSG |
| `+1` | LFO — регистр `$22`, но только если взведён бит 3 |
| `+2` | бит 6 включает **особый режим канала 3**; байт уходит в регистр `$27` |
| `+3` | алгоритм (биты 0-2) и обратная связь (биты 3-5) — регистр `$B0` |
| `+4` | панорама, AMS, FMS — регистр `$B4` |
| `+5`…`+10` | оператор 1: `$30` DT/MUL, `$40` TL, `$50` RS/AR, `$60` AM/D1R, `$70` D2R, `$80` D1L/RR |
| `+11`…`+16` | оператор **3** — те же шесть регистров со смещением `+4` |
| `+17`…`+22` | оператор **2**, смещение `+8` |
| `+23`…`+28` | оператор 4, смещение `+$C` |
| `+29`…`+36` | частоты отдельных операторов для особого режима канала 3: `$A6`/`$A2`, `$AC`/`$A8`, `$AD`/`$A9`, `$AE`/`$AA` |
| `+37` | маска операторов для key-on: уходит в старший ниббл регистра `$28` |
| `+38` | не используется ни в одном разобранном месте; у 151 записи из 156 там ноль |

Операторы лежат в порядке 1, 3, 2, 4 — так же, как они разложены по
регистрам самой микросхемы. Регистры `$90`-`$9C` (SSG-EG) драйвер всегда
обнуляет.

**Проверка на данных.** Во всех 149 тембрах FM — это 596 операторов — ни
один неиспользуемый бит отображённых регистров не взведён: ни бит 7 в
DT/MUL, ни бит 5 в RS/AR, ни биты 5-6 в AM/D1R; TL нигде не выходит за
127, а старшие два бита байта `+3` везде нули. Алгоритмы встречаются все
восемь, обратная связь — тоже. У 145 записей маска key-on равна `$F`, у
трёх `$E` (три оператора), остальные выпадающие значения — у записей не
FM, где эти байты значат другое.

Тембр $0F — единственный ударный, и у него `+1` — поправка скорости
сэмпла (драйвер сверяет её с 4 в `$1341`). Что значат 39 байт у типов 2 и
3, не разбиралось.

## Как играется DAC

Самое интересное место драйвера — процедура по адресу `$02B7`, которую
зовут буквально отовсюду, по нескольку раз между соседними действиями.
Это **насос сэмплов**, и он переписывает сам себя:

* в покое по `$02B7` лежит `jr $02DF`, а `$02DF` вписывает туда `exx` +
  `ex af,af'` — с этого момента каждый вызов выдаёт одну точку;
* `$02D0` возвращает исходные два байта (их копия снята при инициализации
  в `$02B3`) и насос замолкает.

Взведённый насос работает так: переключается на теневые регистры (там
заранее лежат `hl = $4000` — порт YM2612, `b = $15`, `d = $1F`), ждёт
переполнения таймера A (`bit 0,(hl)`), перезапускает таймер, берёт байт по
`(de)` и пишет его в регистр `$2A`. Запаковку выбирает **ещё одна
самоправка**: в `$02C4` кладут либо `jr $02EC` (распаковка ниббла), либо
два нуля — и тогда байт уходит в DAC целиком. Решает бит 7 флагов сэмпла
(`$13E5`).

Тик кадра драйвер получает не по счётчику, а хитростью: обработчик
прерывания в `$0038` — это шесть байт, `ld ($003E),sp` и `reti`. Старший
байт стека (`$1B`) попадает в `$003F` и служит признаком «был кадр»;
`$0041` его проверяет, обнуляет и увеличивает `$0040`.

## Как это послушать

Разбор говорит, что драйвер сыграет; проверить это можно единственным
честным способом — дать ему сыграть. `make z80render` запускает код Z80 на
эмуляторе и пишет то, что этот код выдаёт в YM2612 и PSG:

```bash
make z80render                                  # все 27 мелодий по 45 с
make z80render RENDERARGS=--all                 # все 169 звуков
make z80render RENDERARGS="--seconds 90 36"     # один звук подлиннее
```

Многодорожечные звуки ложатся в `out/<имя>/sound/music/`, однодорожечные
в `sound/sfx/`, именами `sound_NNN.wav`; стерео, 53 267 Гц — родная частота
отсчёта YM2612, пересэмплирования нет вовсе. Уровень считается **по группе**:
общий множитель на все 169 сразу утянул бы мелодии вниз за самым громким
эффектом.

Из 169 записей таблицы играются 167: у звуков **18 и 82 ноль дорожек** —
пустые записи, и инструмент про них говорит отдельно, чтобы дырка в
нумерации не выглядела потерей.

Эффекты обрываются сами, когда драйвер освободил слоты; мелодии зациклены и
пишутся до предела `--seconds`. Из эффектов в предел упираются семеро — это
тоже петли: 7, 9, 22, 60, 101, 141, 155. Перегнать их подлиннее, не сбив
уровень остальных, можно заданным множителем:

```bash
make z80render RENDERARGS="--seconds 120 --gain 5900 7 9 22 60 101 141 155"
```

Без `--gain` множитель считался бы по этой семёрке и они зазвучали бы
громче соседей. Инструмент предупреждает, если с заданным множителем
что-то упёрлось в предел.

Что при этом происходит. Образ драйвера кладётся в ОЗУ эмулируемого Z80, а
дальше повторяется то же, что делает игра: в кольцо `$1B40` кладутся `$FF`,
команда `$0B` и четыре адреса таблиц, а через два кадра — `$FF $10 номер`.
Ни адреса образа, ни таблицы в инструменте не зашиты: он берёт их из кода
68000 — из загрузчика (две `lea` подряд) и из четвёрки `pea` перед вызовом
инициализации. Сэмплы драйвер достаёт сам, через банковый регистр, как на
живой приставке.

Уровень выставляется в два прохода: сперва всё считается с единичным
усилением, потом берётся один общий множитель на всю выгрузку. Он общий
нарочно — иначе тихие вещи стали бы громкими наравне с остальными, и
сравнивать их было бы нельзя.

Нужны компилятор C и `make deps` (чужие ядра `clownz80` и `Nuked-OPN2`).
Компилятор ищется сам: gcc, clang, а если их нет — MSVC от Visual Studio
(`tools/ccbuild.py`).

## Чего здесь нет

* **Что внутри записи тембра** — 39 байт, из которых разобран только первый
  (тип). Остальное — параметры операторов FM, огибающие и прочее.
* **Таблица 2** (32 байта на запись) опознана по месту чтения, не по смыслу.
* Чем отличаются типы тембра 2 и 3: оба ведут в PSG, но через разные наборы
  каналов (`$1797` против `$17AD`).
* Назначение шестнадцати записей по 39 байт в `$1861` — предположительно
  текущие тембры каналов, прямых доказательств нет.
* Самоправка `$02CF` (для делителей 10 и больше) не объяснена.
