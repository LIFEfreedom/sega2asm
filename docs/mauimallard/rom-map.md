# Карта ROM

Всё ниже получено механически: обходом по потоку управления, подсчётом
ссылок в дизассемблере и измерениями по самому картриджу. Где вывод
предположительный — это сказано прямо.

## Крупными мазками

| диапазон | размер | что |
|---|---|---|
| `$000000-$000200` | 512 Б | заголовок и таблица векторов |
| `$000200-$1D6D74` | 1,86 МБ | графика и уровни; **код сюда не адресуется ни разу** |
| `$1D6D74-$225F9C` | 316 КБ | таблицы и параметры: сюда ведут все 880 абсолютных операндов кода, лежащих в данных |
| `$225F9C-$28D000` | 415 КБ | снова данные без прямых ссылок |
| `$28D000-$2AB83A` | 122 КБ | **код 68000** |
| `$2ABADA-$2AD33B` | 6 241 Б | образ драйвера Z80 (грузится в ОЗУ звукового процессора) |
| `$2AD33C-$2C9000` | 115 КБ | четыре таблицы звука (см. [sound.md](sound.md)) |
| `$2C9000-$2F8C4E` | 191 КБ | сэмплы: средний перепад соседних байт < 25, как у оцифровки |
| `$2F8BF2-$2F8F9E` | 940 Б | звуковой интерфейс 68000 (второе окно кода) |
| `$2F8F9E-$300000` | 28 770 Б | заливка `$FF` до конца картриджа |

Границу `$2C9000` между таблицами и сэмплами взяли по перепаду байт, она
**приблизительная**: точное начало сэмплов знает только драйвер Z80.

## Где код

Анализатор ищет код не по «первой большой заливке» (у этой ROM её нет
там, где надо), а по плотности маркеров — `rts`, `movem`, `jsr.l`, `link`.
Получаются два окна:

```
окна кода: $28D000-$2AC000 $2F8000-$2F9000 (всего 131072 байт из 3145728)
```

Внутри них обход по потоку управления подтверждает **115 680 байт кода**
(30 547 команд, 138 сегментов `m68k`) — 88% окон. Остальное внутри окон —
данные вперемешку с кодом: таблицы переходов, строки, образ драйвера Z80.

Оговорка о том, чего в этих числах нет: код, до которого добираются только
через вычисленный адрес (а не через указатель в ROM), обход не находит в
принципе.

Ещё 46 байт сняты с кода принудительно (`--drop-bin`): двенадцать команд,
которые читались как законные, но при пересборке давали другие байты. Это
таблицы, попавшие внутрь прогона кода.

## Таблицы, которые уже опознаны

| адрес | записей | что |
|---|---|---|
| `$1FCBAC` | столько же | список объектов для расстановки; тот же индекс, что и у `$1FCC08` |
| `$1FCC08` | 164 | процедура инициализации уровня; индекс — `$FF1B14` |
| `$1FD014` | 273 | состояния игрока; индекс — `$FF2130` |
| `$1FBC5C` | 141 | длинные слова в код, потребитель не найден |
| `$1FF5F0` | 136 | то же |
| `$1FD7AC` | — | что-то меню: адрес кладут в `$FFFFFD74` при старте |

Записи всюду по 4 байта, значение — адрес процедуры. В `$1FD014` часто
повторяется `$2A526C` — это не заглушка, а процедура, которая сама зовёт
процедуру по указателю в `d0`.

## Текст

Текст лежит **обычным ASCII**, заглавными буквами, строки разделены нулём.
Ни тайлов, ни своей кодировки — `.tbl` этой игре не нужен.

| адрес | что |
|---|---|
| `$1E967C-$1EA216` | вступление: «SHABUHM SHABUHM, A POWERFUL MOJO IDOL, HAS PROTECTED THIS ISLAND FOR CENTURIES.» и дальше по сюжету, 163 строки |
| `$1EA641-$1EAA34` | ещё 29 строк |
| `$1FD443-$1FD79F` | меню: `START`, `OPTIONS`, `PASSWORD`, **`DEBUG`**, `DIFFICULTY` (`NORMAL`/`HARD`/`PRACTICE`), `SOUND TEST`, `CONTROLS` с четырьмя раскладками кнопок |

Меню записано **дважды**: один вариант без `DEBUG`, другой с ним. Какой из
них показывается и чем включается — не установлено.

## Из чего состоят данные

Классификация по 32-килобайтным блокам: энтропия и средний перепад соседних
байт. Приём грубый — он отличает сжатое от несжатого, но не скажет, тайлы
перед ним или карта уровня.

| диапазон | энтропия | вывод |
|---|---|---|
| `$000200-$1B0000` | 3,5–4,5 бит/байт, нулей 30–50% | графика, но **не готовые тайлы** — см. ниже |
| `$1B0000-$208000` | 5,5–6,8 | таблицы, палитры, текст — сюда и смотрит код |
| `$208000-$288000` | **больше 6,9** | **карты имён VDP**: слова «приоритет, палитра, отражения, 11-битный номер тайла». Энтропия высокая потому, что номера не повторяются, а не от сжатия |
| `$288000-$290000` | ниже 5,5 | снова графика |
| `$2C8000-$300000` | перепад байт < 25 | сэмплы |

Палитры лежат **без сжатия**: 64 слова подряд в формате `0BGR`. Проверено на
`$1F0612` — все 64 слова корректные цвета, ни одного лишнего бита.

### Графика лежит готовыми тайлами

Низкие банки — несжатые тайлы 4bpp, уходящие в VRAM прямой передачей DMA;
распаковщика в игре нет вовсе. Доводы и разбор очереди DMA —
в [graphics.md](graphics.md).

Здесь стоит запомнить только одно: **`$001000` — не графика, а таблица
длинных указателей**. Именно на ней первый заход и ошибся, решив, что
тайлов в низких банках нет.

## Заливки как ориентиры

Больших однобайтовых заливок в картридже всего пять:

| диапазон | байт | чем забито |
|---|---|---|
| `$105CF8-$106BF8` | 3 840 | `$FF` |
| `$10D298-$10D698` | 1 024 | `$30` |
| `$10F058-$10F458` | 1 024 | `$11` |
| `$1FB1DC-$1FBBDC` | 2 560 | `$00` |
| `$2F8F9E-$300000` | 28 770 | `$FF` |

Две заливки осмысленными байтами (`$30`, `$11`) — скорее всего пустые
тайловые карты, а не мусор выравнивания.
