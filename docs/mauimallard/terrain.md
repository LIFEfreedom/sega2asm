# Местность: из чего сделан мир

## Код местности у клетки

Байт `+2` в четвёрке метатайла (блок `+$10` графики уровня) — код
местности. Достаёт его `CellTerrainCode` (`$2A5180`), и заодно из неё
видно всю адресацию карты:

```asm
CellTerrainCode:                 ; d0 = x, d1 = y в точках
	movea.l	($FFFFE124).w,a1 ; карта: слово на клетку
	movea.l	($FFFFE140).w,a2 ; свойства метатайлов, по 4 байта
	lsr.w	#4,d0            ; -> столбец
	lsr.w	#4,d1            ; -> строка
	lea	($FF0020).l,a3   ; ТАБЛИЦА СМЕЩЕНИЙ СТРОК, длинное на строку
	add.w	d1,d1
	add.w	d1,d1
	move.l	($0,a3,d1.w),d1  ; начало строки
	add.w	d0,d0
	add.w	d0,d1
	move.w	($0,a1,d1.w),d0  ; слово клетки
	lsr.w	#1,d0            ; слово/2 = номер метатайла * 4
	move.b	($2,a2,d0.w),d2  ; +2 записи — код местности
```

Два попутных вывода. Первый: **`$FF0020` — таблица смещений строк карты**,
по длинному слову на строку; её же берут все остальные щупы. Второй:
`слово / 2` вместо `(слово / 8) * 4` — то же самое, и это подтверждает
разбор блока `+$10` в `tools/levels.py`.

## Свойств у местности ровно одно

`$1FCF14` — таблица байтов по коду. Ненулевых записей **три**:

| код | значение |
|---|---|
| 2 | `$01` |
| 28 | `$03` |
| 80 | `$01` |

И **все девять читателей во всём ПЗУ проверяют только бит 0**:

```
$292610  btst #0,($0,a2,d2.w)     $29C384  btst #0,d2
$293A58  btst #0,($0,a2,d2.w)     $29C3B2  btst #0,d2
$29523C  btst #0,($0,a2,d2.w)     $29D82A  btst #0,d2
$2A51F6  btst #0,($0,a6,d3.w)     $2A1ED0  btst #0,d2
$2A5208  btst #0,($0,a6,d3.w)
```

Бит 0 — «не пройти». **Бит 1, поднятый у кода 28, не читает никто.** То
есть никакой «воды, шипов и лестниц» в таблице местности нет: у местности
одно свойство, твёрдая она или нет. Шипы и всё прочее опасное — это
объекты с уроном (см. [enemy-catalog.md](enemy-catalog.md)).

Читатели показывают, зачем это нужно, и все пять случаев разные:

| место | что делает при твёрдом |
|---|---|
| `$29C384` | `neg.w $16(a0)` — отскок по горизонтали |
| `$29C3B2` | `neg.w $18(a0)` и звук `$0F` — отскок по вертикали |
| `$2A1ED0` | НЕ двигает пару объектов, если впереди стена |
| `$295244` | зовёт `loc_299CC6` — упёрся |
| `$2A51BC` | считает, **через сколько клеток вниз будет твёрдо** |

`CellTerrainSolid` (`$2A51BC`) — это луч вниз: `dbf` по строкам, на каждой
проверяются ДВЕ соседние клетки (`+$0` и `+$2`), и возвращается номер
строки, где встретилось твёрдое.

## Подъём воды

Отдельной «воды» в местности нет, а вот **поднимающийся уровень** есть, и
устроен он тремя вещами.

**Линия.** `$FF1390` — мировая координата Y поверхности. Двигает её
объект с обновлением `$2A179A` (одна клетка на уровне 11):

```asm
loc_2A179A:
	lea	($FFFFE1CA).w,a1
	movem.w	$12(a1),d0/d1          ; игрок
	move.w	($FF1390).l,d2
	cmp.w	d2,d1
	blt.s	loc_2A17BA
	move.w	#$FFFF,($FF1A6C).l     ; игрок НИЖЕ линии -> выход из уровня
	bra.s	loc_2A17D6
loc_2A17BA:
	subq.w	#1,$6(a0)
	bpl.s	loc_2A17D6
	move.w	($FF1392).l,$6(a0)     ; период
	subq.w	#1,d2
	move.w	d2,($FF1390).l         ; линия поднимается на точку
	move.w	d2,($FF04F2).l
```

Период `$FF1392` ставится равным **4**, то есть линия идёт вверх на точку
каждые четыре кадра. Провалиться ниже неё — `$FF1A6C = -1`, тот самый
сигнал выхода из кольца занятий.

**Разрыв растра.** `$FF04F2` — та же линия, но для рисования. `$295A70`
переводит её в экранную, зажимает по `$D0` и по надобности **взводит или
снимает обработчик строчного прерывания**:

```asm
	move.w	($FF04F2).l,d2
	sub.w	($FFFFE1BE).l,d2       ; минус камера
	bpl.s	loc_295A88
	moveq	#0,d2
loc_295A88:
	cmpi.w	#$00D0,d2
	bgt.s	loc_295AB2             ; за экраном — снять
	move.w	d2,($FFFFE19C).l
	...	loc_2A5776               ; поставить $295D18
```

`$FFFFE19C` — **номер строки для разрыва**, и это доказывается тем, как её
используют: `$2A5288` кладёт её в регистр 10 VDP (`ori.w #$8A00`).
Значение `$FFFF` означает «разрыва нет»; в меню там стоит `$BE`.

**Что происходит на строке.** Обработчик `$295D18` захватывает шину Z80,
дожидается гашения по биту 2 состояния VDP, отключает дальнейшие
прерывания (`$8AFF`) и льёт в CRAM блок по указателю `$FF0502`:

```
слово       сколько записей минус одна
на запись:
    слово   индекс CRAM (к нему прибавляется $C000 — команда записи)
    3 слова три цвета подряд
```

Между записями стоит пустой `dbf` на 38 — то есть цвета меняются **по
ходу луча**, строка за строкой. Ниже разрыва палитра другая.

Формат проверяется сам собой: у `$1EABEC` в заголовке `$0005`, то есть
шесть записей по 8 байт — 50 байт вместе с заголовком, и ровно через 50
байт начинается следующий блок, `$1EAC1E`. Блоки лежат встык без зазора.

| блок | цвета |
|---|---|
| `$1EABEC` | `0000 0200 0222`, `0422 0244 0466`, `0688 08AA 0220`, … — зелёно-жёлтая рябь |
| `$1EAC1E` | `0000 0222 0444`, `0666 0888 0AAA`, `0CCC 0EEE 000C`, … — серая лесенка в синий |

Ставит указатель `loc_295C86` и соседи: у каждого свой блок, `$FF1A28` —
флаг «обработчик уже взведён».

Сам разрыв ставят **процедуры уровня** (поле `+$2C`, см.
[engine.md](engine.md)): `$2A5F5E` берёт `$FFFFE12E` минус `$1C`,
`$2A5FDC` — минус `$18`. То есть высота поверхности отсчитывается от низа
уровня.

## Чего здесь нет

* **Бит 1 кода 28** не читает никто. Либо вырезанное свойство, либо
  задел.
* **45 кодов местности из 48 — нулевые**, то есть просто «проходимо».
  Никакого разнообразия местности в игре нет: всё, что не стена,
  сделано объектами.
* Что именно `$1EABE8` (четыре байта перед первым блоком разрыва) — не
  установлено; блоки начинаются с `$1EABEC`.
