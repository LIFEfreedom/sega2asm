# Спецификация уровней

Документ для ремейка, пара к [behavior.md](behavior.md): там — кто как
двигается и бьёт, здесь — **из чего сделан каждый уровень и по каким
правилам он живёт**: карта, местность, кто и что где стоит, чем уровень
кончается, от чего гибнут, что переносится между уровнями, как выдаются
пароли и открывается бонус.

Всё, что здесь перечислено поштучно, выгружает инструмент:

```bash
python tools/levelspec.py              # out/mauimallard/export/levels*
python tools/levelspec.py --level 7    # кто стоит на уровне, по ролям
```

| файл | что |
|---|---|
| `levels.json` | общие правила, легенда местности и сводка по 23 уровням |
| `levels.sources.json` | то же дерево: у каждого числа адрес в ROM (механизм `tools/specjson.py`) |
| `levels/levelNN.json` | сам уровень: сетка клеток, метатайлы, свойства, профили высоты, фон, палитра и **все объекты с координатами и ролями** |
| `levels/levelNN_tiles.png` | тайлы 8x8 по 32 в ряд, индексами цвета: серый `17·i` — цвет i, цвет 0 прозрачен |

**Проверка выгрузки.** Картинка каждого из 23 уровней, собранная только
из выгруженного (сетка, метатайлы, палитра, PNG тайлов), совпадает с
рендером `tools/levels.py` **до точки** — различий 0 на всех уровнях.

## 0. Как устроен уровень

Номер уровня `$FF1B14` выбирает запись в таблице `$1FCB50`; разбор всех
полей — в [engine.md](engine.md). Для движка из записи нужно вот что:

| поле | что | в JSON |
|---|---|---|
| `+$00` | палитра, 4 ряда по 16 цветов CRAM | `palette_cram` |
| `+$04` | таблица профилей высоты, по 16 байт | `profiles` |
| `+$08` | графика: карта, метатайлы, тайлы, свойства, фон (LZSS); у уровня 0 ещё вторая карта столкновений (`+$18`/`+$1A` записи графики) | `cells`, `metatiles`, `metatile_props`, `background_names`; `shadow` |
| `+$0C`, `+$10`, `+$14`, `+$34` | прокрутка и фон ([camera.md](camera.md)) | `scroll` |
| `+$18`, `+$3A` / `+$1C` | анимация тайлов / палитры | `tile_animation`, `palette_animation` |
| `+$20` | таблица порождения: код клетки -> конструктор | `spawn_table` |
| `+$24` | таблица касаний: код -> обработчик ([behavior.md](behavior.md), 2.2) | `touch_table` |
| `+$2C` | процедура уровня: всё, чего нет на карте | `level_proc`, `level_proc_does` |
| `+$36` | старт игрока, X и Y | `start_px` |
| `+$3C` | номер музыки | `music` |
| `+$3E` | вязкость (ненулевая: полскорости по X, падение до `$0C00`) | `sticky` |
| `+$40` | уровень последний в мире: после победы заставка | `cutscene_after` |

**Карта.** Клетка 16x16. Слово клетки / 8 — номер метатайла; метатайл —
четыре имени VDP («лево-верх, право-верх, лево-низ, право-низ»): номер тайла
в битах 0-10, отражения в 11 и 12, ряд палитры в 13-14, приоритет в 15. У
каждого метатайла четыре байта свойств ([levels.py](../../tools/levels.py),
`props`):

| байты | что |
|---|---|
| `+0`, слово | смещение в таблице профилей: высота земли в каждом из 16 столбцов клетки, считая от верха; 0 — земли нет |
| `+2` | **код местности** (раздел 1) |
| `+3` | **код порождения**: объект, который заводится, когда клетка въезжает в окно камеры |

**Объекты.** Отдельной расстановки в игре нет — только коды порождения в
метатайлах. Код ведёт в таблицу `+$20` (конструктор) и в таблицу `+$24`
(что будет при касании). Отсюда три правила, которые ремейку надо
повторить:

* объект появляется, когда его клетка въезжает в окно, и **разбирается,
  уйдя из окна** — потом появится заново (`ObjectReleaseCell`);
* **убитый не возвращается** до перезахода на уровень: `loc_299CF8`
  стирает у него номер порождения и клетку;
* место рождения — угол клетки плюс сдвиг, который прибавляет сам
  конструктор (обычно +8, +8 — середина). В JSON у каждого объекта уже
  стоят итоговые `x`, `y`, а рядом `cell`.

Роль объекта в JSON (`role`) определена по трём признакам, в таком
порядке: обработчик касания (подбираемое), конструктор (виды противников,
боссы, колдун и опоры, генераторы), процедура обновления (механизмы, имена из
`tools/objects.py`).

## 1. Местность: коды и что они делают

Код местности берут в трёх местах: таблица проходимости `$1FCF14` (бит 0 —
не пройти), профили склонов `$28`-`$30` и **таблица обработчиков под
игроком `$1FD014`**: каждый кадр `$2A4ECA` берёт код клетки в точке
игрока (`+$12`, `+$14`; `$2A516A`), кладёт его в `$FF2130` и зовёт
обработчик. (Сдвиг ±7 по взгляду, который `$2A4EC0` кладёт в `d2`,
затирает первая же команда `$2A516A`, — к X он не прибавляется.) (В [engine.md](engine.md) эта таблица названа «состояния
игрока», 273 записи; на деле это 256 обработчиков по коду местности, а
следом с `$1FD414` идёт таблица восьми наборов снарядов.)

(`$22B01C`). Выгрузка кладёт её в `level00.json` → `shadow.cells` (размер
основной карты; строки игра считает по таблице основной `$FF0020`) вместе с
заплатками палитры `to_shadow` и `to_normal` (номер цвета CRAM и цвета);
`metatile_props` покрывает индексы обеих карт — вторая ссылается на
свойства до метатайла 2994, а метатайлов для рисования 2964.

Ещё две гибели от местности идут мимо кодов: **падение ниже нижнего
предела камеры** `$FF1A92` (`$2A4EA6`: `$FF1A6C = −1`) и **поднимающаяся
лава** уровня 11 (`$2A179A`, [terrain.md](terrain.md)).

## 2. Правила, общие для всех уровней

### 2.1 Чем кончается уровень

Сигнал один — `$FF1A6C`: `+1` пройден, `−1` игрок погиб
([engine.md](engine.md)). Пройденный уровень ведёт к следующему; на 18-м
игра кончается (`cmpi.w #$12`, `$298186`). Кто ставит `+1`:

| что | где | уровни |
|---|---|---|
| клетка выхода, код 5 | `$2A4AF8` | 3-5, 7, 8, 11-12, 14, 16, 17, 19-22 |
| объект выхода | `$29C6D2` | 0, 1 |
| босс повержен | `$2A678E`, `$2A4082`, `$2A778C`/`$2A7BB2`, `$2A6B00`, `$2A81BC`, `$2A95A2` | 2, 6, 10, 13, 15, 18 |
| арена: бойцов не осталось | `$29EDA0`: 121 кадр, звук `$7C`, ещё 91 кадр с тиканьем раз в 32 | 9 |
| идол вернулся домой | `$2A2D56` | 17 |

Бонусные уровни 19-22 кончаются клеткой выхода (`+1`), ударом, после
которого в стопке призов ноль (`$2A003A`, `−1`), или падением ниже
карты в полёте (`$293232`, `−1`) — [bonus.md](bonus.md), 1.

### 2.2 От чего гибнут

| причина | где |
|---|---|
| запас здоровья дошёл до нуля | `$298CDE` |
| упал ниже нижнего предела камеры `$FF1A92` | `$2A4EA6` |
| ниже линии лавы `$FF1390` | `$2A179A`, уровень 11 |
| дух унёс идола за край экрана | `$2A2FDE`, уровень 17 |
| сдуло с палубы: пролом палубы уровня 15 догнал игрока, состояние 32, X правее камеры + 320 | `$293382` ([behavior.md](behavior.md), 1.15) |
| землетрясение: с **5-го** из 8 шагов второй фазы (счётчик `$FF214A` меньше 4) игрок правее `$A8` | `$2994A8`; заводит его `$29BE7C` на **уровне 3**, когда сломан четвёртый из объектов кода 164 (`quake_trigger`, `$29BDCC`): землетрясение, вертикаль камеры стоит ([scrolling.md](scrolling.md), 1.5) |

Гибель при оставшихся жизнях: минус жизнь, уровень заново — **с последней
точки возврата**, если она была.

### 2.3 Точки возврата

Касание объекта-точки (`$2A4664`, коды 48-50) кладёт его место в
`$FFFFFD86`, а номер — в `$FFFFFD8A`, отмечает флаг уровня и играет звук
`$8B`. При старте уровня `$FFFFFD86` побеждает старт из записи `+$36`.
Гасится точка при проходе уровня (`$298148`) и при трате продолжения
(`$2983C2`).

### 2.4 Что переносится, а что сбрасывается

Сброс — `$2983E2`, и он **широкий**:

| сбрасывается | ячейка |
|---|---|
| жетон бонуса | `$FF1350` |
| топливо превращения | `$FF133E` |
| ружьё и выбранный набор | `$FF1A20`, `$FF1A1E = −1` |
| три запаса жуков | `$FF1A22`, `$FF1A24`, `$FF1A26` |
| мешки денег | `$FF1352` |
| форма (снова утка) | `$FF133A` |

| когда | что ещё |
|---|---|
| новая игра (`$29804C`) | |
| **конец мира** — пройден уровень с `+$40` (`$2981A2`) | |
| вход в бонус (`$2982AA`) | |
| **гибель при оставшихся жизнях** (`$29837A`) | ружьё `$FF1A20` сохраняется; запас здоровья и потолок — снова начальные `$FF134A` (прибавка потолка от больших лечилок пропадает); серия ударов ниндзя `$FF1356` −1 |

То есть **внутри мира** между уровнями переносится всё: здоровье,
потолок, жизни, ружьё, запасы, топливо, мешки, форма. На границе мира
ружьё, припасы, топливо и мешки обнуляются — поэтому ружьё лежит на
каждом мире заново (код 22 есть на 14 клетках).

### 2.5 Мешки денег и пароли

Мешок (коды 44-47, касание `$2A45E6`) прибавляет единицу к `$FF1352`, не
больше 50, звук `$61`. После последнего уровня мира идёт заставка
(`$290494`), и на ней **пароль следующего мира показывается, только если
мешков не меньше 12** (`cmpi.w #$000C,($FF1352)` в `$2905EE`). Поскольку
гибель мешки обнуляет, 12 надо собрать за мир без смерти после
последнего сброса.

Таблица `$1FCB26` хранит **последний уровень прошлого мира**, а ввод пароля
кладёт `слово + 1` ([engine.md](engine.md)):

| слово | пароль | ведёт на уровень |
|---|---|---|
| 2 | `ININJA` | 3, NINJA TRAINING GROUNDS |
| 6 | `ILVMUD` | 7, MUDDRAKE MAYHEM |
| 9 | `ITSHOT` | 10, THE SACRIFICE OF MAUI |
| 11 | `GETHIM` | 12, THE TEST OF DUCKHOOD |
| 13 | `YOHOHO` | 14, THE FLYING DUCKMAN |
| 15 | `UNDEAD` | 16, THE REALM OF THE DEAD |
| 17 | `GDLUCK` | 18, MOJO STRONGHOLD |

(`tools/levels.py --passwords` печатает уже `слово + 1`.)

### 2.6 Жетон бонуса

В каждом мире, где есть бонус, **один противник носит жетон**: у него в
байте `+$31` поднят бит 2 (`bset #2,$31(a0)` в конструкторе). Гибнет —
общая смерть `$299CF8` (у мертвецов `$2AB21C`) роняет жетон `$299D70`:
объект с кодом касания 34, подброс `−$0300`. Касание (`$299DC8`) ставит
`$FF1350 = 1`, и после последнего уровня мира `$2982A0` уводит в бонус.

| мир | носитель | уровень | бонус |
|---|---|---|---|
| THE MOJO MANSION | жук, вид 29 (`$29DFDA`) | 0 | 19 (после уровня 2) |
| MUDDRAKE MAYHEM | туземец с копьём, вид 31 (`$29F2F2`) | 8 | 20 (после 9) |
| THE TEST OF DUCKHOOD | туземец с бумерангом, вид 33 (`$2A0E18`) | 12 | 21 (после 13) |
| THE REALM OF THE DEAD | мертвец, вид 34 (`$2A3438`) | 16 | 22 (после 17) |

В JSON у таких объектов стоит `drops_bonus_token: true`.

## 4. Уровни по мирам

Счёт объектов — по клеткам карты; где число противников велико, это
места, а не одновременное население: объект живёт, пока его клетка в окне.

### Мир 1 — THE MOJO MANSION (0-2), особняк

Мир утки: превращения в ниндзя здесь нет (топлива на картах нет).

* **Уровень 0** (`$2A5F6A`): игроку бит 10 — **обычный** облик (без него —
  «тень», [behavior.md](behavior.md) 1.13); флаг `$FF216E = 1` — касания
  только внутри слоя; дворецкие снимаются, пока утка — тень (3.17); **вода**: линия у дна минус `$1C`, под ней растровая подмена
  палитры `$295C86`, на линии два поплавка (`$2A5EC6`); нижний предел

  тени и подсветки VDP (`$8C89`), и если Y игрока при входе **больше**

  выключатель — шкаф-приёмник 190 ([mechanisms.md](mechanisms.md), 1.5).

  минус `$18`). Подъёмники вверх до `$C0` и `$1B0`, спуск до `$300`,

  ([behavior.md](behavior.md), 4.1) и «поднять дно арены до `$F0`».
